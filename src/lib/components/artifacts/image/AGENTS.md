# Image Components

The picture card and panel body of the Image kind (design 5.3-5.10). It plugs into the family's shells (`ArtifactCard.svelte`, `document-workspace/DocumentWorkspace.svelte`, `history/`); it builds no parallel shell. Motion and feel are held to the Document kind's bar (`.superpowers/sdd/MOTION-PARITY.md`).

- **`image-card-view.ts` is the card's one view model**, pure TypeScript fed an `ImageCardView` (server read model) and the component's `$t` and clock. Which takes show (`visibleTakes`: only the server's held automatic retry (origin `auto_retry`) lives in its first take's slot; the model's own retry (origin `retry`) is an ordinary take with its own progress, failure and "Use this"), which one is shown (`shownTake`), the state of a take (`takeState`, with `now` passed in; "starting" shows after `STARTING_SHOWN_AFTER_MS`), the subtitle, the eta words and Before/After availability. Components do not re-derive these; `shouldPollImageCards` calls `hasActiveImageTakes`.
- `failed.unavailable` covers every "cannot reach the picture server" code (`image_server_unreachable`, `image_server_not_configured`), not one. A change reads as words: no "edited ... ago" and no version number (History's fine print only).
- Strings are `artifacts.image.*` in `src/lib/i18n/artifacts.ts`, English and Hungarian; the kind's name is `artifacts.type.image`, the word "Artifact" never reaches the UI. Hungarian "Try again" is "Újrapróbálom" (the retry-button rule in `artifacts.test.ts`).
- **The card** (plan 2b T2): `ArtifactCard` draws the head (`chrome="full"`, kind `image`) and loads `ImageCardBody.svelte` lazily, drawing head and body together; `ToolActivityRow` builds the head from `cardSubtitle` and never an "edited ... ago" line. The chat page answers the card's `ImageCardAction`s (`ImageCardActionHandler`) through `client/api/images.ts`. The picture box is reserved from the take's `box` and never changes height: the state and the picture are stacked layers that crossfade; Before / After floats over the picture (a sliding thumb, transform only); "Use this" sits in the actions row after Another, so the right-aligned "…" never moves; on a narrow card Open › holds its row (faded out) until the picture is an item. Hover feedback in the card is instant (no colour transitions): only transform and opacity animate.
- `ImagePicture.svelte` is the one picture element (card, strip, "Made from", and later the panel and History): aspect-ratio box, `decoding="async"`, fade-in on load, a new picture laid over the old one until it has faded in, `srcset` for `variant: "full"` (thumbnail width from `thumbWidth`, shared with the server's `IMAGE_THUMB_LONG_EDGE`). Its load attachment reads state untracked: a cached picture is complete at once, and a tracked read there loops (`effect_update_depth_exceeded`, found by the motion check).
- **The panel** (plan 2b T3): `ImageBody.svelte` is the kind's body in `ARTIFACT_BODIES` inside `DocumentWorkspace` (the open, dock, expand and phone sheet are the shell's). The picture is fitted by CSS alone: an aspect-ratio box sized with container units (`min(100cqw, 100cqh * ratio, natural width)`) on a `container-type: size` stage, never `object-fit: contain` around it and never a ResizeObserver, so the dock's width animation never re-flows it and the marks (T6) live in the picture's own rectangle. The panel loads the full picture (`ImagePicture` `variant: "original"`); the strip loads thumbnails. Under the picture is one row, reserved whatever it holds: the strip, then the tools (Before / After; T6's Mark). A version landing never moves the picture, and with nothing above it the picture has the rest of the height in every shape (expanded included). The body follows the page's latest version for the item (`ArtifactBodyProps.versionNumber`, from `artifact-versions.ts`): when it rises it reads the item and History's first page again (F23). It registers Download (`/api/images/files/<id>?download=1` with the chat named) and `reload`.
- `VersionStrip.svelte`: one square thumbnail per version, oldest first, read from History's image moments and named in History's words (`moment-text.ts`, never a version number); a frame calls `onOpenHistory(versionId)`, and `HistoryMode`'s `initialVersionId` selects the rail entry that holds that version (`rail-model.ts` `entryKeyForVersion`, F11). One frame per History MOMENT, never per version: Alfy's changes written in a row fold into one moment (F4, its newer picture), and its frame opens History on that moment's own row, so a frame always opens on a row the reader can see, with the same picture.
- **History** (plan 2b T4): the Image is a kind of the family's History (`HISTORY_PREVIEWS.image`, so `kindHasHistory("image")`); the rail, the toolbar and Restore are the shell's. `ImageVersionPreview.svelte` shows the version's picture full size and, when it is compared with another (the version before it, or now), `CompareWipe.svelte`: the other picture underneath, this one over it, cut by a native range input stretched half a thumb past each edge (pointer, touch and keyboard are the browser's own; the thumb's centre is under the hand). The cut is written to `clip-path` (and the line's `transform`) once per animation frame, never through a transition. Marks show on the picture they were drawn on (its `baseFileId` is the one underneath), in `MARK_COLOURS`; the prompt sits in a closed `<details>`. The preview reports no changes, so no stepper. The rail's image moments carry a 40 px thumbnail read in the chat's scope (`MomentRail` `conversationId`, from `HistoryMode`, F25). A picture's versions are named in its own words (`moment-text.ts`: "Alfy made the picture", "Your photo"). `images-history.spec.ts` holds the strip-to-History path (F11) and Restore; the motion check's `t4-*` flows put History open and Restore beside the Document's.
- `pinch-zoom.ts`: `pinchZoom` (an action, on the stage, phone only): two fingers zoom 1x-4x and pan, a double tap resets, another picture (`resetKey`, the file) starts at 1x, one finger and a mouse are left to the Mark tool. Only `transform` moves, written once per frame; `touch-action: none` is on the stage alone and a pinch's pointer events stop there. `zoomFrom` is the pure clamp.
- `BeforeAfterSwitch.svelte` is the one Before / After control (card and panel); `picture-tile.css` is the one tile look (card takes strip and panel version strip).
- `npm run check:image-chunks` holds `ImageCardBody` and `ImageBody` out of the chat route's first load (each fails on a static import); `tests/e2e/images-motion.spec.ts` is the motion check (card: `alfyai-handoff/checks/videos/t2-*`; panel, side by side with the Document: `t3-*`), and `artifact-panel-motion.spec.ts` runs the panel's item checks for an Image as for a Document.
- Pictures load only from `/api/images/files/<id>` (`imageFileUrl`) with the chat's `conversationId`.

Do not:

- add width/height/top/left animation; animate only transform and opacity, tokens only
- import image components statically into the chat route's first load (lazy, like the other bodies)
