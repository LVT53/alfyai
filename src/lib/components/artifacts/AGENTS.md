# Artifact Components

- [`src/lib/components/artifacts/`](./) — `ArtifactCard.svelte` (the one card every kind renders as; `chrome="full"` for the panel list and the four new kinds, `chrome="body"` for a host that draws its own header, today `ToolActivityRow.svelte`'s File row) and `artifact-bodies.ts` (the type→body loader registry; a missing entry IS the File body).
- **The panel's rows and headers** (FB-5, ruling 77: F9, F21, F28, F29). A File has one header wherever it opens from: the chat page gives a produced file that arrives with an artifact id the File kind at the one place every open goes through (`openWorkspaceDocument`, `asArtifactFile`), so `ArtifactPanelHeader` draws it, and the older "Active document" header is only for items that are not Files of the family (uploaded and library documents, Atlas reports). A list row says what tells it from another of its name through `ArtifactCardView.rowFacts` (`components/artifacts/row-facts.ts`: a file's extension and size, and the time when another row shares the name; never a version number, ruling 76), and an item being made again (Regenerate on a deleted card) is a `list.pending` row (`working`), titled and kinded from the chat's own create call (`createdArtifactOf`), not only the card's button. The header's way back is `artifacts.panel.crumb` ("Vissza" / "This chat", it never wraps) named by `artifacts.panel.backA11y` and carries no count (the list's subtitle says how many); the list's own eyebrow is a heading, not a way back.
- **One latest moment** on every surface (list row, in-chat card, panel header's history button, History's top moment): `src/lib/client/api/artifacts.ts` announces every version the server reports with its number, time, author and kind (`subscribeArtifactChanges`); the chat page keeps, per artifact, the highest version and that version's time, author and kind, and reads its rows, cards and open items through `src/lib/client/artifact-versions.ts`. The number orders and guards (`expectVersion`) and is printed only in History's fine print. Never print a latest moment from an open-item snapshot or a list refresh directly.
- The panel header's popovers (Download) share `src/lib/components/artifacts/AnchoredPopover.svelte` (popover on desktop, `DialogShell` sheet on phones; placement in `popover-placement.ts`, kept inside the panel). **One press closes the layer that was on top, as Escape does** (FX-F, FX-B2): a popover is painted in `<body>`, outside the panel's markup, so the panel's outside-press handler (`handleDocumentPointerdown`) answers only while nothing is above it: over a dialog the panel is itself on the dialog stack and asks `isTopmostDialog`, on a page (the Knowledge library, the chat's expanded panel) it is on none and asks `hasOpenDialog()`; a dialog's scrim button takes no focus from a press, so the focus the panel handed back to its row stays there. The version summaries the server writes itself are one vocabulary, [`src/lib/shared/artifacts/version-summaries.ts`](../../shared/artifacts/version-summaries.ts), localized by `history/moment-text.ts`; a body save names its kind (`summaryKind`), never sends text. **Every** summary the server writes comes from it (Alfy's fallback, a comment reply, a kept chat reply, the App's brief and rebuild prompt, "made again" included, never a literal in a service), an Undo or Redo names the version it acts on (`Undid Alfy's change: v7`, `summaryVersion` on the body route, checked against the artifact's own numbers), and the older wordings stay readable: `classifyVersionSummary` reads a row's author and version number into its moment kind, so a model's free text can never pass for the reader's rows (ruling 76, A5).
- **A Download follows its file to the reader's disk, and an export belongs to no reply** (friction audit F1, F30; ruling 77). The Document's PDF, Word and Markdown and the App's `.html` are `produce_file` jobs the panel itself follows: `artifacts/document/DownloadSheet.svelte` (one popover for both kinds) calls `downloadProducedFile` (`src/lib/client/downloads.ts`), which starts the job (`exportArtifactDocument` / `downloadAppAsHtml`), waits for it (`waitForFileProductionJob`, polling the user-scoped `GET /api/chat/files/jobs/[id]`, `getFileProductionJobForUser`; a wait that runs out cancels the job) and then starts the browser's download of the canonical `/api/chat/files/[id]/download`, built from the file's id and fetched through `startAuthenticatedDownload`. The popover says "Preparing your file…" until then and says so, with Try again, when the job failed. The export routes make the job with `origin: ARTIFACT_EXPORT_JOB_ORIGIN` (`file-production/types.ts`, an intake input the server sets and a body never carries), and **no list of a conversation's jobs carries such a job** (`file-production/read-model.ts`: the chat's cards, a turn's start snapshot and `finalize`'s reconciliation, the prompt's job states), so the chat page's end-of-turn stamp (`attachUnassignedFileProductionJobsToAssistant`) only ever sees what the server lists, and it stamps only the jobs made since the turn began (`createdSince`, from the streaming placeholder's time, as the server's own reconciliation does), so no reply is handed an export, or any job from before its turn, as a card. An export is delivery, not creation: it adds no File row to the panel's list (the board's PNG is the one export that does, ruling 18) and no row of the Knowledge library (its source row is marked `artifactExport` and never promoted to durable; the library lists no row so marked). The same item, as it is now, in the same format is the same job: the key is `artifactExportIdempotencyKey` (id, format, a hash of the title and body) and the routes ask for `reuse: "usable"`, so a repeated press is handed the file it made, and a job that failed, was cancelled or lost its file lets go of the key. A failure after the popover has closed is a toast. Do not attach an export to a reply, start one without following it, or put a second download path beside the canonical route. The session probe a download starts with (`SESSION_PROBE_URL`) is a request meant to succeed.
- **"Artifact" is never shown in the UI** (ADR-0066): every user-visible string, `title`, and `aria-label` names the kind (Document/Dokumentum, App/Alkalmazás, Canvas/Tábla, Slides/Diasor, File/Fájl) through `artifacts.type.*` in [`src/lib/i18n/artifacts.ts`](../../i18n/artifacts.ts); the word itself is fine in code, tables, routes and file names.


Do:

- keep the type→body registry and `ArtifactCard.svelte`'s kind branches append-only, one entry per kind per slice


Do not:

- add a second type-label i18n family beside `artifacts.type.*`, or let the word "Artifact" reach a user-visible string
