# Read Aloud In The Browser

The browser side of read aloud (spec `docs/superpowers/specs/2026-11-16-read-aloud-design.md`, §4.1–§4.5, §4.8, §4.9): the speech script built from the rendered reply, the marks drawn over it, the reading machine and the controller that carries out its commands, and the language detector. The server side, which checks every request and is the speech service's only reader, is `src/lib/server/services/read-aloud/`.

- **The script is built from the rendered DOM only, never from Markdown** (spec §4.4: no syntax reaches the voice). `speech-script.ts` walks the reply's `.markdown-container` text nodes, so what is read is what is on screen, and every word keeps a `Range` over its own characters for the marks.
- **Marks never change the reply's DOM or its layout.** They are an overlay behind the text (`ReadAloudMarks.svelte`, `z-index: -1`), and the prose is isolated (`isolation: isolate`) only while it is marked, so the marks can never paint over the composer layer (spec §4.2). Nothing wraps, splits or styles the reply's own text nodes.
- **The reply controller owns its `<audio>` element and the session routes; the voice preview (`voice-preview.ts`) owns the one element every ▶ in Settings and the editor plays through, and the preview route. Components never touch either element, and never fetch.** `controller.ts` owns the reply's element, the `EventSource`, the timers and the calls in `src/lib/client/api/read-aloud.ts`; components read `readAloudView` and call the controller. `voice-preview.ts` owns the preview's element, its renders (the last 12, as object addresses, revoked when evicted or disposed) and `renderVoicePreview`; components read `voicePreviewView` (`src/lib/stores/read-aloud.ts`) and call the preview. The voice and preference routes are called through `src/lib/client/api/read-aloud-voices.ts`, from the Settings card and the editor.
- **The iOS unlock happens synchronously in the press handler.** On the page's first press, before anything is awaited, the controller plays a silent clip on its audio element; iOS then allows that element's later plays. A press handler that awaits before calling `start` loses the unlock. The voice preview's `unlock()` is called the same way: synchronously in the click that opens the editor and in every ▶ handler, before the render is awaited.
- **The detector is the one exception to "no second reader"** (owner, 2026-11-16; written in `src/lib/server/services/chat-turn/AGENTS.md`, after I4). `language.ts` (tinyld, loaded lazily) names each paragraph's language only to pick a voice and the speech service's text rules, and to name a language that has no voice. No model request, title, chip, record or route reads it, and nothing in `chat-turn/` imports it. tinyld never enters the chat's first paint (`check:artifact-chunks --chat-forbid tinyld`).
- **Spoken forms come only from `src/lib/shared/read-aloud/spoken-forms.ts`**, the code the session route checks every token with (`wordsFitReply`). Nothing else makes up a spoken word: a token the dictionary does not make fails the containment check, and the reading never starts.
