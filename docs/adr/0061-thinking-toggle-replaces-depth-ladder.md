# A single Thinking toggle replaces the Reasoning Depth ladder

> Note on numbering: the task that produced this ADR asked for `0057-thinking-toggle-replaces-depth-ladder.md`, but `0057` was already taken by `0057-memory-v2-internal-hardening.md` (an unrelated ADR landed concurrently). This document is `0061`, the next free number at merge time.

Accepted. AlfyAI replaces the three-value **Reasoning Depth** control (`Off` / `Auto` / `Max`, resolved through a deterministic keyword classifier into `off` / `standard` / `extended` / `maximum` applied profiles) with a single user-facing **Thinking** toggle: `thorough` (thinking on, the default) and `quick` (thinking off). This **supersedes the `Off`/`Auto`/`Max` control and Automatic Depth Selection from [ADR-0028](0028-normal-chat-reasoning-depth.md)** (as amended by **[ADR-0046](0046-automatic-depth-selection-is-deterministic.md)**, which made Auto's classifier deterministic instead of an LLM preflight). Everything else those ADRs describe — Depth Metadata, Depth Observability, retry/reconnect carrying depth forward, and the shape of persisted metadata — stays, because old messages and clients still carry the old values.

## What changed

- **The toggle, not a ladder.** `ReasoningDepth` is now `"thorough" | "quick"` (was `"off" | "auto" | "max"`). `thorough` is the default. `quick` only turns provider-native reasoning off — it does **not** cut tool-step or web-source budgets, unlike the old `Off` profile, which ran a visibly smaller budget (8 tool steps / 4 sources vs. standard's 14 / 6). `quick` and `thorough` now use the identical 14-step / 6-source budget; the only difference is `providerReasoning.thinkingMode` (`off` vs. the existing `standard` behavior) and grounding guidance (`minimal` vs. `standard`).
- **No more classifier.** `resolveReasoningDepthSelection` (`depth-selection.ts`) is a direct, synchronous mapping — `quick` → applied profile `off`, `thorough` → applied profile `standard` — with no keyword tables, no "simple auto" fast path, and no reuse of a previous turn's signals for an explicit `Max`. The `[DEPTH_CLASSIFIER]` log line is now `[THINKING] source=toggle mode=quick|thorough`.
- **The composer UI.** The reasoning-depth picker (a dropdown inside the composer tools menu) is gone. In its place, `MessageInput.svelte` renders a `Brain`-icon toggle button in the toolbar, next to the incognito and connections toggles, following the same icon-only-colouring pattern. It is not rendered at all when the selected model's capabilities explicitly mark reasoning controls unsupported (`supportsReasoningControls: false`, newly exposed on `GET /api/models`). The `/depth` slash command no longer opens a menu section (that section no longer exists) — it flips the toggle directly.
- **Persisted/localStorage values migrate, they don't break.** `parseReasoningDepth` (now the single canonical parser, in `reasoning-depth-types.ts`) accepts the current toggle values and the legacy wire values: `"off"` → `quick`, `"auto"` / `"max"` → `thorough`, and falls back to the legacy `thinkingMode` field for clients that never sent `reasoningDepth` at all. The settings-store migration and message-metadata reader (`hasValidDepthMetadataBase` in `messages.ts`) apply the same rule, so a pre-migration `localStorage` value or a message persisted months ago still loads correctly.

## What stays (deliberately unreachable, not deleted)

`DepthAppliedProfile` keeps all four values (`off | standard | extended | maximum`) rather than shrinking to two, because `depth-metadata-types.ts`, message persistence, the `MessageBubble` depth badge, and old persisted messages all still reference `extended`/`maximum`. Concretely, this means:

- **`reasoning-depth-effort.ts`** still fully implements `extended`/`maximum` budget scaling and provider-reasoning-effort mapping — it is simply never asked to compute them for a fresh turn, since nothing produces those applied profiles anymore.
- **Normal Chat Deliberation Passes** (ADR-0028) and the **Depth Clarification Gate**'s high-cost trigger are both keyed off `appliedProfile === "extended" | "maximum"`. With the toggle only ever producing `off`/`standard`, both are now permanently bypassed for new turns — they are dormant, not removed. They still matter for messages persisted before this change and for the Depth Clarification carry-forward path (a follow-up turn after an old clarification).
- The clarification gate's unused model-classifier injection point (`depthClarificationClassifier`, threaded through `shared-normal-chat-model-run-helpers.ts` and `streaming-normal-chat-model-run.ts`) is untouched by this ADR — it was already unused before this change and is out of scope here.
- `buildReasoningDepthEffortGuard` (`normal-chat-context.ts`) keeps its `extended`/`maximum` branches for the same reason; they're unreachable from a fresh turn but still correct for effort objects built from old data.

## Why this shape

The old ladder's value came from `Auto` genuinely not knowing the right effort ahead of time — a real three-way decision worth a classifier. Once the decision comes directly from a user-flipped switch instead of inferred intent, there is no longer a meaningful "let the app decide" state, and the classifier scaffolding (keyword tables, fast paths, previous-turn signal reuse for `Max`) was solving a problem that no longer exists. Collapsing `off`'s budget cut was a deliberate product decision: `quick` should feel like "skip the extra thinking," not "get a worse-equipped assistant" — the same tools and sources are available either way.

## Consequences

- **`docs/adr/0028-normal-chat-reasoning-depth.md` and `0046-automatic-depth-selection-is-deterministic.md` are superseded** for the `Off`/`Auto`/`Max` control and Automatic Depth Selection specifically. Their deliberation-pass, Depth Clarification, and Depth Metadata content is still accurate as a description of dormant/legacy-carrying machinery.
- **CONTEXT.md** glossary entries for **Reasoning Depth**, **Off Reasoning Depth**, **Max Reasoning Depth**, **Automatic Depth Selection**, and the retired **Depth Classifier Model**/**Depth Classifier Resilience** entries need rewriting to describe the two-value toggle; see the glossary update landed alongside this ADR.
- Do not read "extended"/"maximum" applied profiles or deliberation passes running on a fresh turn as a bug — they are only reachable through Depth Clarification carry-forward from a pre-migration message.
- A future change that wants deliberation passes back for `thorough` would need a new decision — this ADR does not reintroduce the ladder, only documents that its machinery still compiles.
