## Original findings

1. **P1. A second identical resend can submit an already accepted assertion again.** Accept a chat fact, delete its message as part of an identical resend, then delete that replacement as part of another identical resend before its source job settles. Once the jobs drain, the last resend succeeds in the fixture but sends one native retain with a new document ID. The retain carries the original assertion timestamp and the current assistant context. This reproduces a redundant retain and change of physical owner. The fixture gives the new owner the same fact ID and supplies no evidence about native duplicate visibility. `unchangedSourceInventory` examines the immediate, unsubmitted predecessor and authorizes first retain without resolving the earlier accepted owner on the same chain. Deferred cleanup also protects only a direct queued successor. Use the existing scoped predecessor and owner proof across the bounded chain of verified edit withdrawals. Consume the same transition chain in cleanup and publication. Preserve the ordinary-deletion and expired-transition controls. [Inventory](../../../src/lib/server/services/memory-profile/curation-runner.ts#L1568) · [Retain dispatch](../../../src/lib/server/services/memory-profile/delivery-runner.ts#L498) · [Cleanup claim](../../../src/lib/server/services/memory-profile/delivery-job.ts#L38)
2. **P1. Remove cannot rebuild an accepted dependent reply that was itself exactly resent.** Learn decaf and an independent tyre fact, then accept a reply that reformulates decaf and independently mentions sorting stamps. Exactly resend the reply. It shows an accepted logical tip with no native retain. Removing decaf hides the reformulation immediately and leaves the tyre fact visible. The job deletes the dependent's physical document, then fails before a rebuild with `memory_source_changed` at the old message check. Remove reaches terminal `memory_preparation_failed` and the independent stamp fact stays excluded. The repair plan identifies a physical owner whose message was deleted during the successful resend. Validate the current logical tip and its persisted content through the same exact-owner lineage used for curation. Carry that proof through cleanup and re-admission. A deleted or ambiguous tip must still forbid rebuild.
