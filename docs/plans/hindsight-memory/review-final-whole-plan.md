## Integrated checkpoint findings

1. **P1 · Historical import can upgrade uncertain text without Include in the same stored second as an enabled interval starts.** Both message creation and control interval boundaries use second-resolution timestamps. First preparation opens an enabled interval and re-reads both timestamps during inventory. It accepts equality at the interval start and the eventual dispatch check consults the same values. Persist a legacy chat at 12:00:00.100, with no consent record or known interval, and begin prepare at 12:00:00.900. Both values become 12:00:00 on disk and the source is marked eligible. The permission rule should treat equality at the start as ambiguous when reconstructing historical policy, with explicit Include, trusted live acceptance and conservative known-off handling preserved. Exercise the scheduled delivery and capture actual text-bearing requests. [Column precision](../../../src/lib/server/db/schema.ts#L345) · [Opening interval](../../../src/lib/server/services/memory-profile/migration.ts#L81) · [Permission rule](../../../src/lib/server/services/memory-profile/history-eligibility.ts#L36) · [Dispatch recheck](../../../src/lib/server/services/memory-profile/revisions.ts#L403)
2. **P1 · An interrupted history withdrawal can leave imported facts available after Decline is stored.** The choice transaction commits before the awaited import/prepare path. A crash or failed preparation between these steps leaves old accepted historical rows, no revocations and no cleanup jobs. Subsequent list/detail/recall admission accepts their still-current publication, even though status now reports Decline. There is no durable handoff for the intervening failure. Commit choice, revocation and source cleanup intents through the existing atomic job enqueue boundary. Preserve known-on and new live sources. Exercise interruption with an earlier accepted historical import and a fresh read of the previous generation. [Choice and prepare](../../../src/lib/server/services/memory-profile/migration-policy.ts#L119) · [Publication admission](../../../src/lib/server/services/memory-profile/publication.ts#L786) · [Existing cleanup transaction](../../../src/lib/server/services/memory-profile/migration.ts#L181)
3. **P1 · A stale recall can send the query to Hindsight after the learn/recall gate closes.** Recall captures the account and its personal/project banks before network I/O, then waits on each request in turn. There is no source/scope check after the authenticated capability lookup or private alias resolution before the text-bearing POST. Pause capability, switch Memory off or move the chat, and release capability. The final result fence rejects stale evidence, but the query has already been sent. When the first bank's query was already legally dispatched, a state change before its response can still precede a second-bank POST. Reuse the existing transport dispatch callback to recheck the owned conversation, scope, lifecycle, epoch and control revision right before POST, keeping the final result fence. Verify the wire, including that a memory off/on cycle cannot redeem an older attempt. [Recall loop and result fence](../../../src/lib/server/services/memory-context/native.ts#L26) · [Transport dispatch seam](../../../src/lib/server/services/memory-profile/hindsight-client.ts#L118) · [Recall request](../../../src/lib/server/services/memory-profile/hindsight-client.ts#L273)
4. **P2 · A repair-blocked bank suppresses healthy sibling recall.** When dependency discovery exceeds its proved bound, the engine intentionally fences the affected bank. The recall selection originally excluded retired banks only. Reading a repair-blocked project bank throws during final admission and discards the healthy personal bank's results, or vice versa. Skip the explicitly blocked bank at selection and recheck its live status during final admission. The affected bank stays held, including its own UI publication. Preserve global permission checks and surface unexpected admission failures through their existing paths. [Overflow transition](../../../src/lib/server/services/memory-profile/dependency-repair.ts#L273) · [Recall admission](../../../src/lib/server/services/memory-context/native.ts#L54)
5. **P1 · Successful preparation while Memory is off can revoke previously accepted memories.** Turning Memory off is a pause. The prep inventory excludes chat text because the master control is off and similarly filters authored actions. Stale-source reconciliation then uses those temporary exclusions to revoke accepted imported chat and authored sources. This can happen during the normal awaited follow-up to Decline while off. Re-enabling cannot restore the previous native document IDs once cleanup runs. Separate paused ingestion from evidence becoming unauthorized. Preserve already accepted, still-permitted records while allowing the optional-history withdrawal itself and other genuine revocations to settle.
