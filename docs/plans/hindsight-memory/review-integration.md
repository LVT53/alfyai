# Independent integration and privacy review, 2026-11-18

**Request changes. The native replacement is unfit for cutover at this checkpoint.** I reproduced a revoked fact reaching chat, an original statement from a disabled period entering a personal bank, removed conversation context reaching a later native request, and two ways physical erasure fails.

The eleven existing focused suites passed 89 tests on Node 22. I then ran six independent negative-control probes against migrated synthetic SQLite databases, the real application read/delivery paths and the real job ledger. The probes reproduced all six defects they assert. Their HTTP transport was simulated. I verified the relevant HTTP contracts in the unmodified local Hindsight checkout at `9fb28dbd724dc1ce4da7cb4c49008e601db76c5f`. No live service was started. The source/action validator and new HTTP adapters were under active development and need their own review once integrated.

## Findings requiring implementation changes

1. **P1 — A revoked personal memory reaches the model from a project chat.** `src/lib/server/services/memory-context/native.ts:57–97,138–146` appends each bank's admitted rows to the result before awaiting the next bank. Removing the first bank's source while the second request was in flight still returned its exact removed text. The bug affects both passive injection and the explicit persona tool. A same-epoch off/on also evades the account epoch comparison. Collect rankings first, take one final synchronous admission snapshot of all the selected rows, and recheck owner, originating conversation/project, authority, control revision, epoch, and live source/fact revocations after all network awaits. Preserve native ordering within the budget. This implementation iterates SQLite rows and uses native results only as a membership filter, so a weaker match can also displace a stronger one.

2. **P1 — Live intake assigns consent and scope at completion instead of at the original turn.** `src/lib/server/services/memory-profile/chat-delivery.ts:45–99,151–158,216–238` applies historical eligibility only to preceding sources. The current message requires only an enabled account and the chat's *current* project. In the migrated fixture a persisted user message dated inside a recorded off interval, originally in a project, was processed after the chat moved out. Its text became a new personal source and a job was enqueued. A delayed stream projection can run this sequence between persistence and intake (`chat-turn/finalize.ts:1013–1031,1067–1075`). A turn begun off and completed after enabling can also appear wholly new because `finalize.ts:624` creates the user message on completion. `chat-turn/stream-completion.ts:991–1010` maps a failed reset-fact read to undefined and intake treats that as permission to skip the check. Capture trusted source eligibility, project, native epoch and monotonic controls at turn acceptance. Fence the same values alongside original persisted identity at staging and final dispatch. Unknown controls, a moved source and stale receipts must omit learning while chat remains usable. A normal regenerate without a fresh user receipt already exits early.

3. **P1 — Removed prior context is sent as part of the next source.** `memory-profile/chat-delivery.ts:100–188` serializes prior user and assistant text into the new source. `memory-profile/delivery-runner.ts:263–288` checks only that new source before transmitting the saved context verbatim. I admitted an earlier turn, packed a dependent reply, revoked the earlier source, then drained the normal engine. The recorded native POST still contained the revoked token. Delaying or replaying a later queued revision can transmit that token even after the original's document cleanup. Represent dependencies by source/message IDs and fingerprints, including the user assertion authorizing each assistant context item. Re-resolve them against live source/fact revocations, deletion, scope, eligibility and original content at the last dispatch boundary. Omit unsafe context. If a submission already occurred, preserve idempotency while reconciling and cleaning any dependent stored document before claiming removal. Restrict preceding messages by sequence as well as time: the current timestamp-inclusive query can select later messages from the same second.

4. **P1 — Physical erasure can be blocked forever by ordinary historical work or by its verification request.** `memory-profile/delivery-job.ts:139–151` puts every previously submitted retain into the erasure job, including accepted sources. `delivery-runner.ts:35–46,139–159,179–185` waits on all IDs and treats an expired receipt as unknown. The native status API explicitly prunes completed operations after its retention window (`hindsight-api-slim/hindsight_api/api/http.py:7908–7913`). With a previously accepted source returning the documented `not_found`, my engine run never sent DELETE. Second, `hindsight-client.ts:240–254` confirms bank deletion using GET on the bank root. The pinned root accepts PUT/PATCH/DELETE only (`api/http.py:8245,8290,8336`). Feeding the resulting HTTP 405 to a successful DELETE resulted in a terminal, nonretryable failure. Persist acknowledged terminal status independently of remote operation retention. Reconcile truly ambiguous in-flight submissions separately and keep them pending. Confirm absence using a supported read-only existence operation with verified tenant/404 semantics. Exercise actual native deletion, a predeleted bank, a pruned acknowledged operation, lost acknowledgement and an outage. Unsubmitted documents should require no network cleanup.

5. **P1 — Reset/erase still loses the cleanup handle for work created during reset.** `memory-profile/delivery-job.ts:92–156` correctly commits tombstones for bound retired banks and an epoch advance together. It then cancels and deletes every work row by user ID, including new-epoch work. `account-lifecycle/index.ts:78–95,105–132` subsequently awaits artifact/filesystem work and finally deletes *all* memory banks and sources via `deleteResetScopeRows`. Another process can create and submit a bank in the new epoch during that interval. Its bank was absent from the committed tombstones and the final sweep removes its local binding. Account erasure likewise leaves new admission open before deleting the user. A crash between the separate legacy-reset and native-reset commits also advances just one fence. Use a durable erasing state to block writes during the destructive operation, or consistently filter cancellation/local deletion by retiring epoch and safely preserve post-reset work. Store the cross-authority boundary atomically, resume unfinished work after a crash, and retain every bound remote handle until cleanup is acknowledged. Test two connections with a barrier before the final wipe.

6. **P1 — Source removal, disabling Memory and source delivery still have crash gaps.** `memory-profile/chat-delivery.ts:216–238,270–298` commits source creation/revocation separately from job insertion. `memory-profile/migration-policy.ts:245–309` commits off before asynchronous imports, broadly cancels work, and later creates cleanup jobs one by one. Killing the process after local revocation but before enqueue strands a sent native document. A failure during an awaited step can leave later documents without a job. A rapid enable plus a new source can have that new source revoked by the unfinished off path. A stream-process restart after its durable receipt but before deferred intake also loses the turn absent a durable reconciliation record. Atomically bind each source/retirement and its durable intent through the engine. Scope off cancellation to the retired control revision. Exercise process death and off/on interleavings, plus abandoned edit resends.

7. **P1 — Deleting a project leaves the native project bank and manual data behind.** `src/lib/server/services/projects.ts:403–438` only revokes sources belonging to the project's current conversations. Create a project, add a standalone scoped memory, then delete that project. There need not be any conversation to revoke. The bank, manual sources/actions and remote index remain, and no native bank cleanup is scheduled. Local read checks hide the project. The owner-export code can also abort a whole archive when it enumerates an orphaned project bank and the shared scope guard throws (`account-data-archive/index.ts:216–229`, `memory-profile/revisions.ts:206–219`). Retire the entire project bank with a bound durable cleanup intent and fence pending writes in the project deletion transaction. A moved chat still needs source-level retirement and an immutable original-scope rule. Exercise operations while the native service is offline and export other surviving scopes.

8. **P2 — An async preparation callback can mutate SQLite after enqueueAtomic reports rollback.** `src/lib/server/services/jobs/index.ts:62–73` invokes the callback before checking its return value. I passed an async callback that waited at its first await and then changed the account epoch using its tx argument. The function rejected with the documented synchronous-callback error. Releasing the wait committed epoch 77 with zero jobs. Current typed callers use synchronous functions. The runtime contract is a shared engine boundary and should reject an async callback before invoking it and prevent escaped transaction authority from writing. Include a JS/thenable misuse fixture that checks database state after the continuation runs. Ordinary duplicate-insert rollback coverage passes.

9. **P2 — Export drops verified manual edit history.** `src/lib/server/services/account-data-archive/index.ts:230–245` compares action result IDs with `row.id`, a fresh local UUID per snapshot. The read/detail contract binds them to `row.nativeId` plus bank and epoch (`memory-profile/native-read.ts`, `getMemoryDetail`). The test named “exports … explicit edits” seeds no action row. Share the verified, still-admissible history lookup with detail, including operation success, bank, epoch and stable row/lineage identity. Test an actual action, later generation refresh, removal, same native ID in another scope, and master toggle off. Recall references also return local row IDs at `memory-context/native.ts:139`, inconsistent with public list/detail IDs.

10. **P2 — Input packing scales with the user's whole bank on each turn.** `memory-profile/chat-delivery.ts:100–158` loads all accepted, staged and pending source text plus every revocation in the bank and runs separate history-policy DB lookups per source to authorize at most five preceding messages. Restrict lookup to the bounded candidate message IDs and their source/fact dependencies, with appropriate indexes. Verify an unrelated large bank does not lengthen chat tail work linearly. This is additional to F9's publication/writer benchmark.

## Authority, scope and remaining evidence

Native reads select only the personal and active project bank for that user and epoch. Explicit historical-chat access and task continuity have separate owners.
