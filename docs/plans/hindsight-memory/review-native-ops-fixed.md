# Native operations follow-up review

**Request changes.** Five findings close at their original scope. Two remain open where the code can violate the private transport or truthful erasure contract. This review used synthetic fixtures and a read-only health request to the isolated native container.

## Open findings

1. **P1 — Node can route a private request and its credentials through an ambient proxy.** The native factory validates the deployment-approved base before the initial capability bearer and the protected requests reject redirects. The app's shared private transport still delegates to global `fetch` for both literal IPs and pinned alias results. With `--use-env-proxy` in Node 22.23.2, an allowed plain HTTP request went through an ephemeral loopback proxy, which observed the synthetic Authorization header. With the flag omitted, the direct control reached the intended listener and the proxy received zero connections. A separate HTTP redirect requested by the intended listener was refused and the redirect listener received zero requests. The shipped native URL is plain HTTP. This transport also carries curation payloads and its provider credential. Python's upstream and activity clients disable proxy inheritance through `trust_env=False`. Use an explicitly direct agent or dispatcher in the app transport for both paths, and retain the real proxy-enabled negative control. [App private transport](../../../src/lib/server/services/memory-profile/private-endpoint.ts#L57), [Native sender](../../../src/lib/server/services/memory-profile/hindsight-client.ts#L80), [Curation sender](../../../src/lib/server/services/memory-profile/curation.ts#L124), [Node proxy documentation](https://nodejs.org/learn/http/enterprise-network-configuration)
2. **P2 — An already accepted bank creation can outlast successful reset cleanup.** The first Add now commits the binding with its fence before calling native configure, so reset can select the bank for cleanup. A synthetic transport probe through the real app job engine held the native PUT commit, reset the account, observed the cancelled client wait, then let cleanup see config 404 and mark the tombstone succeeded with no native operation IDs. Releasing the server-side write afterward left an empty bank and the app had issued no DELETE. The pinned PUT creates an absent bank and PATCH config can also create one. The probe models a server-accepted write surviving client cancellation. It did not force this timing in PostgreSQL. The observed residue was opaque bank ID and generic bank configuration at most. The second application fence stops the Add text from being retained in this sequence. Preserve the durable binding and settle ambiguous configuration work before representing clean absence as terminal. [First action fence](../../../src/lib/server/services/memory-profile/curation-runner.ts#L269), [Native configure](../../../src/lib/server/services/memory-profile/hindsight-client.ts#L163), [Cleanup 404 fast path](../../../src/lib/server/services/memory-profile/delivery-runner.ts#L144), [Reset sequencing](../../../src/lib/server/services/memory-profile/delivery-job.ts#L132)

The temporary probe harnesses are `/tmp/alfyai-nativeops-rereview-transport.cjs` and `/tmp/alfyai-nativeops-rereview-late-create.test.inc`. The latter uses the setup from `delivery-job.integration.test.ts` and asserts the current failure sequence. Its temporary spec was removed.

## Restore and live evidence

- The hold is environment-owned. An explicit value other than literal `false` keeps the instance held. The SvelteKit startup hook exits before startup work or worker claims, the Memory job definition has its own hold check, and the request hook returns no-store 503 before resolving dynamic routes. The runbook keeps the restored native API stopped and the held app out of public routing. The application guard covers SvelteKit-handled requests. Adapter-node serves packaged static assets outside that hook. [Restore runbook](../../../deploy/hindsight/README.md#restore-hold)
- An older synthetic pair contained one matching SQLite row, two native units and an eligible queued action. The recorded full dev entry point returned 503 on health, authenticated Memory read, machine activity and action submit while the job stayed queued and native startup was withheld. The follow-up substituted a separately verified newer matched pair, then released the hold and observed health 200, zero Memory rows and both banks 404. This exercises quarantine and replacement with a verified current pair. Replaying or merging an incomplete privacy journal into an older pair remains unverified. The old pair stays isolated if reconciliation cannot be established. [Quarantine and release results](native-acceptance/restore-quarantine-results.json)
- I cross-checked the pinned scratch source revision, container build and restart records, and the 19 allowed, nine forged-key-denied, four cross-tenant-denied method results. A read-only check of the isolated container on port 18894 returned health 200. The recorded PostgreSQL outage and native restart produced 200, 503, 200 and 200. These observations qualify that tested image and service instance. Capability identity attests the engine and tenant schema identity, while restore pairing requires separate checks. [Container method results](native-acceptance/container-methods-results.json), [Restore readback](native-acceptance/restore-results.json)
- The real app gateway trial measured three baseline foreground calls at 1.59–2.03 s and three calls started with six admitted background requests at 1.79–2.17 s. Every burst rejected one extra request while all 18 admitted requests completed. The gateway's process-local budget is one when daytime or activity is unknown, six on fresh healthy idle, and one for further admissions on active. These short direct-gateway bursts verify open requests, not sustained provider work, end-to-end job fairness or cancellation at the model after client timeout. [Overlap results](native-acceptance/app-overlap-results.json)
