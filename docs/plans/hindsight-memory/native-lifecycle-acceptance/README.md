# Native Memory lifecycle acceptance

**The integrated lifecycle did not pass.** Both languages learned fresh facts, applied a direct correction and preserved unrelated and third-party information through replay and a database restart. English partial removal was rejected and temporarily lost the previously accepted fact from chat recall. Hungarian whole removal blocked future publication after acknowledging exclusion. A cancelled edit also stranded a surviving dependent reply. The scope and reset cases passed. One applied fault-case correction kept a replaced detail in a valid native raw annotation.

The original findings below are preserved. A later fresh Hungarian retest passed whole removal and admitted the newer assertion. [Targeted native retest](followup.md)

## Method

These cases ran the real app's enrollment, completed-turn delivery, job engine, native curation, publication, Memory list/detail/action routes and persona recall. The harness supplies synthetic logged-in locals to route handlers and persists a constant acknowledgement except where a scripted assistant question is part of a dependent reply. Each case uses an independent migrated SQLite file and fresh UUID account and tenant. The native worker is Hindsight `9fb28dbd724dc1ce4da7cb4c49008e601db76c5f` with a disposable pgvector PostgreSQL 18.1 database, ONNX embeddings and FlashRank. Its bridge permits only the configured local Flash Next alias `qwen3-6-27b`. The alias does not verify the model's size. [Runner](run.ts) · [Authored inputs](fixtures.json) · [Isolated fault relay](relay.ts)

The supplied data includes only authored messages, exact action drafts and natural questions. The following judgments were made offline from valid native raw rows, native observations, accepted app publication, actual persona tool payload, source details and job/action ledgers. Where a checker rejected, its output describes the mechanism. The checker's judgment supplies no credit for facts, attribution, or privacy. The synthetic clock separates original authorship, correction, omission, replay and genuinely newer assertion.

## Dirty edit cancellation

The original statement was that the user teaches a pottery class on Mondays. The next reply confirmed it and independently stated that the user maintains a community seed library. Native consolidated a single pottery observation linked to both source documents. A separate chat supplied an unrelated preference for paper maps.

The relay forwarded a real native fact PATCH while changing the schedule to Fridays and obtained HTTP 200. It then used the app preferences handler to turn off Memory before returning that acknowledgement to the job. The job cancelled, the draft document was cleaned from native storage, active app reads were off, and the dirty edit still had a durable rollback checkpoint. While off, the app deleted the original pottery message and withdrew native support from both the root and the dependent reply. After enabling, the child remained `repair_held`. The rollback inventory required its still-linked source to be `accepted` and terminated with `memory_edit_restore_source_changed`; ordinary repair remained paused. The independent seed-library statement was unavailable. Paper maps remained visible and a new wind-chime fact failed with `memory_curation_publication_held`. No Monday or Friday assertion appeared in active recall after deletion. [Cancellation records](evidence/cancel.json.gz)

A separate fresh run rejected the comparable schedule edit before its first PATCH and preserved the baseline in native, publication and recall. That run did not exercise dirty cancellation. [Additional rejection](evidence/cancel-prewrite-rejection.json.gz)

## Isolated failure paths

The relay forwarded all ordinary requests to the real native service. Faults only affected the requesting synthetic runner. A simulated persistent curation gateway 503 hit three app attempts and settled as retryable failure; all preexisting facts still appeared in both UI and recall. An explicit retry used a delayed response of four seconds. The local model returned, but the substantive edit later failed checking and preserved the same accepted publication. A malformed planner response requeued once and then applied its corrected observation, preserving the third-party beetle fact. A malformed final checker response after a real PATCH also requeued once, then applied the requested burgundy typewriter and allowed a later unrelated assertion.

**False acceptance in native storage.** The published burgundy proposition and admitted recall were clean. The valid raw fact appended `Explicit source edit changed the typewriter's color from lilac to burgundy`. The operation had applied despite carrying the replaced detail in a native annotation. The separate synthetic action audit can record what was changed. This detail also persisted in the active raw fact after the action settled.

During a separate persistent post-PATCH malformed response test, the job rejected all three attempts and reported retryable failure with cleanup pending. The old burgundy card stayed in the accepted Memory page, but admitted recall omitted it and native already held the staged mint correction. Mint stayed out of both the page and recall. After disabling the fault, an explicit retry resumed the same job, applied mint and restored a complete recall result, including Maja's beetle studies and the timer hobby. The terminal failure interval therefore preserved exclusion of the unverified draft, with a recall availability gap for the old accepted assertion. All 172 calls actually forwarded to the local Flash Next bridge returned HTTP 200. The injected failures were local to the relay. ## Reproduction and limits

From the repository root, use Node 22 and the pinned scratch Hindsight evaluation environment from the operations report. Replay uses the actual app and native services. Keep all input synthetic. The bridge logs only the synthetic model prompts and responses in this scratch run. [Scratch native setup](../native-operations-fixes.md)

1. Create a fresh directory under `/tmp/alfyai-lifecycle-acceptance`. Start the existing synthetic Flash bridge from `../native-acceptance/proxy.cjs` on 18891 with its trace in that directory. Start the scratch Vite app as the admission service on 18893 using a fresh SQLite path, unique Vite cache and bearer `synthetic-activity`. Start the pinned native API at 18890 with its activity URL pointing to `http://127.0.0.1:18893/api/internal/memory-admission` and upstream local bridge 18891. Set `ALFYAI_NATIVE_DATABASE_URL=pg0://alfyai-native-lifecycle-acceptance-20261118` only for the named disposable PostgreSQL instance used for these records. Use a different disposable instance for a fresh repetition.
2. Run `ALFYAI_LIFECYCLE_RUN=<unique-name> /opt/homebrew/opt/node@22/bin/node --import tsx docs/plans/hindsight-memory/native-lifecycle-acceptance/run.ts <en|hu|cancel|privacy|faults>`. The runner refuses an existing SQLite or JSON path in first mode. Each process writes an atomic record next to the SQLite file. Set `ALFYAI_LIFECYCLE_EDITS_ONLY=true` for an EN/HU comparison ending after partial removal. On hosts with restricted loopback, run the authorized loopback probes with the sandbox's approval flow.
3. After English and Hungarian first stages, stop the scratch native API and restart it against the same disposable PostgreSQL database. Run the same per-case commands with a final `after-restart` argument. Native changed PID 73109→89297 and PostgreSQL 73201→89411; each app harness also ran in a new process. `continue` recovers these recorded checkpoints from a stopped harness. It does not simulate a worker crash while an assertion is in flight. `persistent-fault` adds a prolonged checker outage after a real PATCH to the completed fault fixture.
4. Read the archived records with `gzip -dc evidence/en.json.gz | jq '.steps[] | {name, operation, applicationRecall}'` from this directory. Each inspected checkpoint stores valid raw facts, observations, accepted generation and fingerprints, source messages, action draft and versions, admitted recall, revocations, and real attempts. The records include initial source hashes and deltas at each resumed process launch. The product checkout was dirty. Concurrent fixes changed dependency/rollback code during the assay and curation code between phase launches. Major scenarios with a later product fix need a new run with a single settled fingerprint.
5. For the privacy case, the archive contains the independent SQL query results. `verify-reset.py` checks that the three IDs belong to the exact synthetic tenant and only reads its named disposable PostgreSQL instance. It requires a runnable scratch pg0 instance for a fresh read.

This run did not exercise the production build, a browser, the user-interface display of history, or backup/restore. The pinned API/PostgreSQL restart happened between settled operations. These small cases do not establish overnight throughput or steady-state concurrency. The prior broad benchmark covers recall/answer quality separately.
