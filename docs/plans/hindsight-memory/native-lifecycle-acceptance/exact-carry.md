## Accepted manual correction and later resurrection

A separate English case started with Earl Grey tea and aunt Mara's oboe. The user edited the displayed preference to jasmine tea on August 4. The correction applied and invalidated the original Earl Grey fact. The next exact resend used the original wording without a retain, local model prompt, or native mutation. Jasmine and Mara's fact and observation IDs were exactly the same after the resend, with dates August 4 and August 2 respectively. The following dependent reply received the accepted jasmine and Mara facts as `prior-memory`. Earl Grey was absent from its retain context.

The changed edit then appended only “I bake rye bread every Sunday” to the original message and used the messages route to remove the later reply as part of that edit resend. The new document carried only the bread fact dated August 10. The app separately passed the carried jasmine fact into the proposal for the old chat's before/after text. The first proposal preserved jasmine. The checker then called the unchanged old Earl Grey wording authoritative and requested a repair. The repaired proposal replaced jasmine with Earl Grey, and both the repeated and final checks accepted.

The relay recorded HTTP 200 for an actual PATCH to the same native raw fact ID and manual document that had supported jasmine. Its text became Earl Grey and its date stayed August 4. The manually authored source itself still reads “I prefer jasmine tea.” Native observations, published Memory, and actual chat recall showed Earl Grey. Plain deletion removed the old physical chat ancestry and bread, yet Earl Grey remained admitted because it now occupied the separate manual document. A stale edit pointer still made zero retains and created no source receipt. A never-submitted rosemary assertion subsequently made one first retain at its original date. The positive exact-resend and first-delivery results therefore stand on their own, while this changed-resend sequence is a false acceptance. ## Reproduce

Use the scratch services and settings in the [baseline setup](README.md#reproduction-and-limits). Run the repository-root Node 22 command with a fresh `ALFYAI_LIFECYCLE_RUN` and one of `carry-en` or `carry-hu`. The main English and Hungarian modes attempt a manual correction. Set `ALFYAI_LIFECYCLE_CARRY_NO_CORRECTION=true` for the lamp control without a prior edit, or `ALFYAI_LIFECYCLE_CARRY_METRONOME=true` for the English metronome variant. Use `ALFYAI_LIFECYCLE_CARRY_TEA=true ALFYAI_LIFECYCLE_CARRY_TRIM_REPLY=true` for the separate applied manual correction and changed-resend path. No service restart is required.
