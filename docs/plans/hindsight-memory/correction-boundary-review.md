# Independent native correction boundary review

2026-11-18. Source-only review; no model calls, product changes, or new runtime tests. Confirmed pinned Hindsight checkout `9fb28dbd724dc1ce4da7cb4c49008e601db76c5f`. Read alongside [native quality follow-up](native-quality-followup.md) and [bounded-update evidence](bounded-update-results.md).

**Conclusion: keep extraction native. Deterministic delivery/replay protection can remain a bounded application component. Selectively reconciling a changed compound fact is a separate semantic problem; native provenance does not make that problem disappear. It need not run on every ordinary retain.**

## What native code already does

1. **Identical retain is different from forced reprocess.** Native retain compares chunk content hashes at the same chunk indices. Unchanged chunks keep their facts, while changed/removed chunks cascade-delete their facts and derived observations. If no chunk is unchanged, it falls back to full replacement. A short chat message is commonly one chunk, so appending one unrelated sentence can replace all that message's facts. The existing runtime failures are consistent with this behavior. [Chunk diff](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/retain/orchestrator.py#L3964), [fallback](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/retain/orchestrator.py#L4134), [changed-chunk deletion](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/retain/orchestrator.py#L4535).
2. **Forced reprocess deliberately defeats unchanged-content deduplication.** It reloads original document text/retain parameters, then forces extraction even when content is identical. Therefore successful identical retries cannot establish durable curation across reprocess. [Reprocess](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/memory_engine.py#L14502), [forced extraction](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/retain/orchestrator.py#L1973).
3. **A native fact is a prose assertion with document/chunk provenance, not a stable semantic slot.** The extraction schema contains what/when/where/who/why, entities and causal relations; it does not establish independently addressable ownership/colour/price fields or verified per-subclaim source spans. Public unit detail exposes document ID/chunk ID and current payload. It does not supply a semantic identity that survives arbitrary paraphrase or re-extraction. [Fact models](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/retain/fact_extraction.py#L170), [unit detail](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/memories/pg/curation.py#L319).
4. **PATCH has useful metadata controls but preserves causal edges.** It can replace text, context, dates and entity associations, and re-embed/re-consolidate. For hand-authored entities the source recommends `resolve_entities:false`, avoiding fuzzy merging into the wrong entity. However, its documented implementation deliberately preserves extracted causal edges when text changes. The public PATCH schema exposes no replacement causal-edge list. A corrected text alone therefore cannot certify that every graph assertion was corrected. [Engine contract](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/memory_engine.py#L13028), [public request](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/api/http.py#L2979).

## Clean boundary worth testing

Keep a small durable record only for user-curated items: source lineage/revision, original native payload fingerprint, exact accepted replacement or removal, scope, action revision, and acknowledgement. Use one stable message/document identity rather than repeatedly re-ingesting a whole conversation. New ordinary messages continue through native extraction; they do not need the correction model simply because some other fact was edited.

Handle delivery separately from interpretation:

- Same source revision and same payload: use the cached accepted edit; no model needs to rediscover it.
- Older delivery/retry after a newer source/action/reset: reject by monotonic source/action revision and epoch before publication. Native internal content hashes protect parts of native concurrent writes; they are not AlfyAI's desired-revision contract.
- New source revision, unchanged native fact: exact **scoped** original-payload matching can carry the accepted edit to a recreated raw ID. Match within known source lineage, with relevant dates/context/ownership metadata and multiplicity checks. Do not match solely on globally identical prose: two people or projects may have the same sentence, and the same words at a later date can describe a new event.
- Changed native fact in a curated lineage: reconcile only those candidate facts. Keep unrelated acknowledged facts available while withholding disputed claims. This is the narrow semantic seam. A whole-source freeze or withholding all its unrelated facts would fail the agreed behavior.

An immutable replacement document preserves the accepted correction across worker retries and gives a durable publication target. **It does not by itself suppress an old claim emitted elsewhere**, decide whether a changed source describes a genuine later event, or preserve unrelated subclaims when invalidating a compound native fact. It is storage identity, not a substitute for scoped reconciliation. Similarly, a repeated paraphrase in a different source needs affected-set discovery; nearest-neighbour search can find candidates but does not prove exhaustive suppression.

## Important constraints

Hash equality is a useful fast path, not a fuzzy semantic solution. Hash the pre-curation payload separately from the accepted payload. Re-extraction can change language, grouping, entity resolution or dates without the user changing the underlying claim; nonmatches require a conservative semantic path rather than an automatic overwrite. Native delta-retain can also update metadata/tags on unchanged units, so text equality alone is insufficient for publication acknowledgement.

Do not pass unfiltered native source chunks, entity/graph payloads or Reflect results to the answer path. They can bypass corrected text, including preserved causal links. The existing guarded Recall boundary should expose only admitted text/evidence and verified relevant metadata. Native derived observations may be fresh yet semantically wrong; provenance freshness is not a truth test.

The approach remains bounded integration if it owns delivery state, explicit curation intent, affected-source reconciliation and publication, while native extraction/retrieval/consolidation remain intact. It becomes a replacement memory engine if it requires a universal entity/property ontology, every-turn extraction/classification, global semantic truth resolution, or permanent paraphrase bans. The current evidence does not establish that those larger mechanisms are necessary, but also does not prove the smaller semantic seam reliable yet.

**Next decisive evidence:** independently test cached exact carry-forward, stale revision rejection, changed grouped facts, duplicated text with different owners/scopes, genuine later events, and replay with altered metadata. Report deterministic mechanism passes separately from model-dependent preservation. No source-only review can certify the latter.
