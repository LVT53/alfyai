# Memory replacement UI review — 2026-11-18

**Request changes.** The list, detail, editor and removal view exist. The Knowledge switcher and Guide spotlight survive. The new views use the shared error component, motion wrappers, real drawing controls and bilingual copy. The current code fails several privacy, navigation, recovery and acceptance requirements in Tasks 5–6. This checkpoint reviewed the working tree against the agreed design and its actual interactive HTML, independently of the implementer's summary.

## Findings requiring changes

Line numbers refer to the checkout at the time of review. `View` below is `src/routes/(app)/knowledge/_components/KnowledgeMemoryView.svelte`. Sibling Memory components and CSS are in the same directory.

1. **P1 — a pending detail read can replace a newer screen or draft.** View lines 96–105, 161–170, 359–362. Select a row and open Add before the detail returns. Alternatively, refocus the browser on detail and enter Edit while its background detail request is pending. The old response still calls `setView("detail")`. A late failure can also put a stale error on the newer screen. Capture navigation and scope identity per request, invalidate reads on any navigation, and refresh detail in place without refocusing the reader. Cover late success and failure.
2. **P1 — stale review can expose old-scope rows and use the wrong mutation reference.** View lines 225–253, 384. Review fetches an unfiltered first page, assigns it to the visible list, follows with a detail read and stores its result globally. Neither read checks scope, navigation, row identity or mount. Cancel, return to the list and switch projects before it resolves. The response can replace the new project's page with the previous project's records. A row from page two cannot be reviewed even if its identity survives. Bind review to the original record, current view and scope. Fetch the exact current authorized row by identity or traverse the full snapshot. If identity no longer exists, explain this and allow recovery with the draft. Keep the list's search and pagination independent.
3. **P1 — stale/exclusion flags apply to unrelated memories.** View lines 141–150, 169–182, 189–208, 382–395. After an acknowledged removal with cleanup pending, cancel/back out, then open another memory. The old cleanup notice remains and both actions on the new record are disabled. A 409 opening a row from the list sets global stale state even when there is no current detail to review. Another row can inherit the stale state. Associate operation, stale review and feedback with the affected scope/ref, keep exclusion effective for that ref, and clear unrelated controls on navigation.
4. **P1 — closing a transient polling error strands the operation.** View lines 65–69, 258–260, 295–304, 379. Return a queued result, fail one operation GET, and close its error. Polling stops; its retry closure is removed while Back, Cancel and Save remain disabled indefinitely. Leaving the tab unmounts the component, loses the operation ID and stops monitoring. Reconcile the durable operation independently of the dismissible alert, resume on return, and keep an accessible status/recheck action. Reopening after an unknown response must preserve idempotency.
5. **P1 — ordinary Save can duplicate an action after a lost acknowledgement.** View lines 306–351; MemoryEditor lines 30–34. An Add POST can commit while its response is lost. The toast Retry retains the original ID but Save creates a fresh ID for the same draft, allowing duplicate additions. Changing the draft then clicking the old toast Retry submits the old text behind the current editor. HTTP refusals other than 409 all receive Retry, even a permanent refusal. Distinguish unknown acknowledgement, terminal refusal and a new intent; reconcile/retry the original request when uncertain, and make the visible draft and action agree.
6. **P1 — immediate Remove success leaves a blank screen.** View lines 189–191, 283–293, 334–354. If the initial POST returns applied (including an idempotent replay), `settle` clears the detail and calls `back()` while `submitting` is still true. The busy guard returns and the remove view no longer has a detail to render. Return to the list on confirmed success through an internal completion transition that bypasses the user-action guard. Verify both immediate and polled success. Also handle an applied edit/add with a failed detail refresh without leaving Save enabled to submit the completed action again.
7. **P1 — source links do not fulfill exact message navigation.** MemoryDetail line 46 links to the correct parameter. `src/routes/(app)/chat/[conversationId]/+page.svelte:2991` returns if the initial window lacks the message and never requests its older page. Line 2994 calls the scrolling-only function, while the existing highlight is applied at 2655. Line 2593 always smooth-scrolls, including with reduced motion. Use an authorized target window or the existing older-messages reader; revalidate the navigation, scroll to/highlight the actual source, honor reduced motion and show an unavailable result if it disappears. Browser test by clicking a source outside the initial window and a deleted source, not by inspecting href. Coordinate this isolated change with the chat page owner.
8. **P1 — chat evidence still exposes legacy memory actions.** `src/lib/components/chat/MessageEvidenceDetails.svelte:278,320–347` recognizes legacy memory fact IDs and fetches a projection revision to send suppress, retire or correct payloads to the shared action route. `src/lib/client/api/knowledge.ts:411–480` still exposes the replaced profile, overview, summary and timeline calls. Opening evidence from an old chat after cutover offers actions whose payloads no longer identify a valid current memory. Retire these controls or resolve the authorized current identity and use the new actions only where established. Test legacy evidence after cutover. Also remove/gate the superseded home review destination for legacy users still routed to the new Knowledge tab; the old destination section no longer exists.
9. **P1 — global reset status cannot distinguish pending remote deletion.** `src/lib/client/api/settings.ts:533–543` discards the response and `src/routes/(app)/settings/+page.svelte:1107–1110` unconditionally announces that memory and knowledge have been cleared. The confirmation at `src/lib/i18n/settings.ts:874–877` promises deletion. When the native service is offline, local exclusion and native cleanup have separate outcomes. Carry that status across the privacy route/client into Profile and provide the specified visible retry/recovery or display completion only after verification. This depends on the privacy backend work in progress.
10. **P2 — initial, failed and background list states are misleading.** View lines 70–76, 107–135, 388; MemoryList lines 43–51. Before authority is known an Add is available. A failed initial read displays “Nothing remembered here yet” alongside the error; dismissing it leaves only the false empty state. A successful read retry never clears the earlier alert. A failed load-more retries page one, losing prior results. “Updating” has no future refresh scheduled unless the user changes focus; background retry merely reads the failed status and dismissal silences other scopes' later failures. Separate unknown/error from accepted-empty, disable writes until eligibility is known, scope errors to their request, preserve page position on retry and track pending/failed background work to its actual outcome.
11. **P2 — source attribution is inferred from missing data.** MemoryDetail lines 45–46; `src/lib/memory-types.ts:33–51`. An empty sources array is labelled “Added by you” without proof of a manual add. An unavailable source always renders “You wrote” and its quote, including when unavailable means unauthorized or when the backend redacts the quote. Require provenance-backed attribution; hide inaccessible quoted text, show the honest unavailable state and use the shared localized conversation-display fallback for untitled chats.
12. **P2 — an introductory choice can reappear after dismissal; import status can become stale.** `src/lib/components/ui/MemoryHistoryImportNotice.svelte:23–29,45,53–69`. In the introduction, open the choice dialog then dismiss with Esc, X or backdrop. Only the editor closes, so the prompt immediately remains and reappears after reload. Profile cancellation should preserve the saved choice, while introductory dismissal must suppress repeated prompts. Successful retry of a failed Profile status load leaves the alert displayed. Concurrent loads are unsequenced, the owning instance's unmount suppresses notification to the still-mounted shell after a successful save, and pending/working status never advances without another load. Distinguish prompt dismissal from opening/cancelling Profile, reconcile current durable status and clear recovered feedback. Cover two tabs and component teardown.
13. **P2 — the approved hover highlight is missing.** `memory-replacement.css:125–126` uses `--surface-hover`, which has no definition in the source tree. The browser drops the background value; only the chevron moves. Use the established theme hover treatment and verify computed hover background, row inset and reduced-motion behavior on the actual product.
14. **P2 — navigation loses position outside the simplest in-view Back.** View lines 101–104, 152–159, 189–198, 359–362; Knowledge page line 857. After opening a deeply scrolled row, the view is replaced without scrolling its new heading into view. A background refresh collapses the paginated list to page one, so Back can no longer focus a later-page row. A source-chat visit followed by browser Back remounts the Memory component at Personal with a blank query. Preserve per-visit navigation state for the selected scope/query/pages/focus/scroll and give each new view an explicit visible focus target. Restore after source navigation without persisting private drafts or accepting stale content.
