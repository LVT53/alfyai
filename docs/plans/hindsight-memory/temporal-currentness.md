# Temporal currentness in Hindsight Memory

An assertion can remain valid historical evidence after it stops describing the present. Current Memory should recall enduring facts and still-active plans or situations. When the evidence supplies an explicit end, current recall should stop at that end. An explicit lookup of an earlier conversation remains governed by the separate chat-history permission and scope rules.

This document records local evidence and a proposed design. No production records were inspected for this investigation and no temporal policy was activated.

## What the legacy investigation established

Two synthetic reproductions passed against the legacy compatibility implementation, along with 65 existing tests.

- An English location correction from temporary to durable inherited the old deadline. The Judge's update changes the statement and records provenance without updating the expiry class or deadline. The projection writer preserves expiry unless its patch explicitly supplies a value. The inverse transition can leave a time-limited fact without a deadline by the same code path. Only the durable correction was reproduced. [Judge update](../../../src/lib/server/services/memory-judge/index.ts#L332) · [Projection write](../../../src/lib/server/services/memory-profile/projection-store.ts#L579)
- A Hungarian temporary apartment search expired and disappeared from the active item list. The stored persona summary still returned the claim. Legacy prompt assembly fetches that summary independently of the active item list and includes its text without revalidating supporting facts. The reproduction exercised expiry and summary readback. Prompt exposure follows from the assembly code. [Summary read](../../../src/lib/server/services/memory-consolidation/summary.ts#L241) · [Prompt assembly](../../../src/lib/server/services/memory-context/persona.ts#L96)

Source inspection identified two further failure modes. Intake and review compute the factual horizon relative to processing or approval time, which can shift dates for old evidence. Renewal uses the row's mutable update time as a proxy for fresh evidence, so unrelated writes can qualify an item. An existing regression test confirms that the legacy 30-day extension alone does not cause indefinite self-renewal. The reproductions establish mechanisms. They cannot establish the frequency or cause of individual historical outcomes. [Intake expiry](../../../src/lib/server/services/memory-judge/index.ts#L495) · [Review expiry](../../../src/lib/server/services/memory-profile/review.ts#L119) · [Renewal](../../../src/lib/server/services/memory-consolidation/steps.ts#L109) · [Renewal regression](../../../src/lib/server/services/memory-consolidation/steps.test.ts#L773)

## What the native evidence can establish

AlfyAI's published generation records each accepted raw fact's identity, text, native mention date and canonical assertion date. Its observation display date is the latest support assertion. Retain, edit and replay can change storage timestamps without creating a newer user assertion. [Native contract](../../../src/lib/server/services/memory-profile/contracts.ts#L10) · [Publication](../../../src/lib/server/services/memory-profile/publication.ts#L1216)

The installed staging engine at the pinned revision combines the earliest occurrence start, latest occurrence end and latest mention across an observation's support. Those aggregate values can describe several claims of different ages. Native occurrence timestamps describe an event interval. They carry no guarantee that a particular claim expires at the interval end. The public recall API's time window affects ranking and permits results outside the window. These surfaces cannot be used as enforceable claim deadlines. [List memories](https://docs.hindsight.vectorize.io/api-reference/list-memories/) · [Recall memories](https://docs.hindsight.vectorize.io/api-reference/recall-memories/)

## Proposed correction

- Keep Hindsight responsible for extraction and consolidation. Apply currentness at the published claim boundary using acknowledged raw support. Keep assertion time, source link, scope and fact-specific effective end distinct. For each effective end, require explicit authored evidence attached to that claim.
- Normalize an explicit end deterministically from the authoritative assertion time and available timezone. Preserve the precision of the wording. For example, an inclusive calendar date expires at the start of the following local day. A duration such as “for two weeks” starts at the assertion only when the source establishes that start. Defer a boundary when the effective date, timezone, inclusivity or referenced event cannot be resolved. Intake, replay, review and consolidation must leave an already resolved boundary at its original instant.
- Preserve enduring qualifiers when a temporary state ends. For example, “I prefer working in libraries, and I am using the branch on Oak Street until Friday” supports a lasting preference and a time-limited location. After Friday the preference remains current if still independently supported. Apply no shared deadline to both. When native consolidation produced a mixed observation, use separately verified claims or preserve the original only as dated evidence until safe separation is possible.
- Use dated historical phrasing for completed events and uncertain or unresolved situations that cannot safely be supplied as current. Do not infer a general lifespan from a fact's age, native mention timestamp, frequency of updates or legacy TTL. A genuinely new assertion may change its claim's horizon. An identical replay and an unrelated sibling update leave the horizon intact.
- Apply the same rule to passive and targeted Normal Chat Memory reads and the current Memory view. Keep effective-end decisions out of owner export and support inspection, where historical evidence may be needed. An expired or uncertain claim must not be reintroduced by a cached summary, a fallback retrieval path, or a model-supplied query. For existing rows without sufficient evidence, surface currentness as unknown for the affected claim. A failed classification or unavailable provider cannot extend its current status.
- Keep source navigation and ordinary Edit and Forget behavior. A confirmed Edit may change only the affected claim, including its effective end where explicitly stated. Forget and source withdrawal remove the applicable support through the existing source and publication fences. They must also prevent reappearance through history replay where those exclusions apply. Expiry alone does not record a user deletion.

## Acceptance coverage

Run English and Hungarian synthetic cases through actual retain, consolidation, publication and both current recall paths. Cover an explicit date across midnight in its timezone, a relative end anchored before delayed ingest, a historical event with an occurrence end, and an unresolved relative reference. Check a mixed row with an older enduring qualifier and a newer temporary assertion, then reverse the source order. Add expiry-crossing edits in both directions and replay with a changed ingestion timestamp. Verify a follow-up remains historical when only old evidence exists, and reassertion only changes current Memory when the new source actually supports it.

Validate the current Memory view, source link and Forget path against the same support state. Include an unavailable or ambiguous temporal result and an old generation or cached summary. The outcome is qualified only when the affected claim ceases to assert a stale present state and the independently supported enduring facts still reach authorized recall.
