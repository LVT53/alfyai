# Independent native curation and provenance review

**Verdict: request changes.** The fresh focused run passed 117 tests across six suites. Four additional synthetic probes reproduced defects using migrated SQLite and production publication, read, or job entry points. The native records independently show a date-renewal false acceptance on a Hungarian omission. The evidence contains synthetic data only.

## Findings

1. **P1 · A changed chat sends historical wording from a different, withdrawn chat to the checker.** An accepted manual Edit whose original row was backed by chats A and B is present in the saved action ledger. Its before text includes B's synthetic private marker. Withdraw B and delete its original message. An edited resend of A appending chess succeeds. The final checker still receives B's marker in `ordered_edits`, although no admitted fact contains it. The current-attempt guard verifies the changed source, while the new action closure builds roots from all rows in scope, including revoked roots, and dispatches their complete saved before/after wording. Require current authority for the full provenance of that wording or provide a bounded, authorized subset. A removed sibling chat must not be sent again while preserving the exclusion intent on eligible sources. [Closure selection and payload](../../../src/lib/server/services/memory-profile/curation-runner.ts#L1884), [dispatch fence](../../../src/lib/server/services/memory-profile/curation-runner.ts#L279), [lineage root resolution](../../../src/lib/server/services/memory-profile/curation-lineage.ts#L76)
2. **P1 · An unrelated Add readmits an earlier corrected value under a replacement observation ID.** Apply a real synthetic Edit to replace green kayak with purple kayak and verify its receipt and original quotation. The next unrelated lamp Add captures a regenerated observation saying green kayak, backed by the exact still-admitted purple raw fact. The Add succeeds and both list and application recall return green kayak. Detail attaches the previous version and original source to this contradictory result. Publication checks the support against accepted raw text while accepting the regenerated presentation without checking its changed meaning. Similar support cannot establish that an incompatible observation represents the accepted edit result. Preserve the accepted result or hold the candidate when an otherwise unrelated publication changes curated observation text without validation. [Add completion and receipt](../../../src/lib/server/services/memory-profile/curation-runner.ts#L1165), [publication support validation](../../../src/lib/server/services/memory-profile/publication.ts#L391), [history rebinding](../../../src/lib/server/services/memory-profile/native-read.ts#L459)
3. **P1 · A shorter Hungarian ownership restatement can acquire the omission date.** In `provenance-raw-v2-hu/hu.json`, the August 5 accepted “A felhasználó távcsöve alumíniumból készült.” becomes “Van egy távcsövem.” on August 7. Possession is already presupposed by the first text. The saved plan puts “The user has a telescope” in `replace` and leaves `preserve` empty. Native retains a new ownership fact, the proposal invalidates the previous one, and the job publishes ownership dated August 7 in raw and list with an applied result. This false acceptance can change precedence against intervening assertions. The same request in `provenance-closure-hu/hu.json` takes the patch-only path and retains August 5. Validate the new-assertion decision independently of the planner before treating a shorter restatement as a new date. [Branch from plan](../../../src/lib/server/services/memory-profile/curation-runner.ts#L949), [immutable new-fact review](../../../src/lib/server/services/memory-profile/curation.ts#L225)
4. **P2 · Exact failed-draft republish can change display when native dates change.** The accepted observation is raw text `green kayak (2026-08-03 12:00: green kayak)` with a rendered row of `green kayak`. Return the same fact ID, text and document and the same native observation text under a regenerated observation ID, but change the raw `mentioned_at` to August 4. Republish accepts the match. The new display exposes the old suffix because formatting is recalculated against the new native time. Verify or preserve the prior display representation in the exact republish path. [Renumbering comparison](../../../src/lib/server/services/memory-profile/publication.ts#L154), [date-sensitive formatting](../../../src/lib/server/services/memory-profile/presentation.ts#L9)
5. **P2 · Revocation can turn an ambiguous retained generation into fabricated unique history.** Publish two observations in one generation, one with the prior Edit's exact kayak support and a second with the same kayak support plus bird. Detail correctly suppresses the earlier receipt. Revoke only the bird source, leaving the generation unchanged. Detail now attaches the earlier receipt because the second row is hidden, although the captured generation is still ambiguous. The export helper reads the whole generation and still omits the link. Apply the uniqueness test to the immutable captured generation, and then separately apply revocation to each linked result. [Detail passes filtered rows](../../../src/lib/server/services/memory-profile/native-read.ts#L369), [export helper passes captured rows](../../../src/lib/server/services/memory-profile/native-read.ts#L426), [support uniqueness](../../../src/lib/server/services/memory-profile/native-read.ts#L452)
