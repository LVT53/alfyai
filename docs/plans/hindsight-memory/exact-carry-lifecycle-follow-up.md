# Exact carry lifecycle follow-up

The application now follows accepted native document ownership when it reads context for the next reply, plans a second changed edit, or finds a dependent reply during Remove. Changed revisions recover physical owners from the accepted `source_edit` receipt in the same user, bank and epoch. The older owners keep their original dates. The existing negative control still rejects an older physical fact when the required receipt is missing.

| Regression | Verified outcome in the application harness |
| --- | --- |
| Remove on a physical fact carried through an exact resend | The dependent duplicate disappears as soon as Remove acknowledges exclusion. The reply is rebuilt from its live assertion and sanitized context. It keeps its independent stamp collecting and receives the unrelated surviving tyre fact. |
| Changed resend followed by a reply and another changed edit | The reply receives both surviving physical facts. The next edit proposal receives both owners, and publication keeps the older facts alongside the new assertion. |
| An extra contradictory observation on an exact resend | The candidate stays held. A no-repair exact resend requires a one-to-one match for displays supported by the carried facts and makes zero retain calls. |
| Native mentioned-date drift during an exact resend | The candidate stays held when a carried fact's native date disagrees with its published fingerprint. It makes zero retain calls. |
| Ordinary deletion of a queued replacement | The deletion retires the older edit-resend transition and queues its physical cleanup. A later attempt using the older pointer creates no source. |
| Deferred cleanup becomes due after a replacement queues | The claim gate gives the eligible replacement its chance to consume the transition. An exact resend publishes without deleting the carried document or retaining again. |
| Deferred cleanup claims the predecessor first | Cleanup closes the admission transition before native deletion. A later request with the expired pointer creates no source or missing-facts retry. |

Deferred cleanup uses the existing 30-minute scheduling boundary. A successor that has already queued in the same account revision can settle before cleanup. Once cleanup is claimed, a late pointer can no longer use that transition. Ordinary new eligible assertions remain eligible through the normal source path.
