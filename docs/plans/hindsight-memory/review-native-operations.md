# Native operations checkpoint review

**Request changes.** The pinned-source deployment and tenant isolation evidence address substantial parts of foundation finding 7. The release configuration still retains sensitive content, documented key rotation breaks curation, and the actual app prevents the idle admission signal from reaching Hindsight. Foundation finding 8 and acceptance gates A1/A4 remain open.

## Findings

1. **P1 — Native tracing stores model content by default.** The environment in `deploy/hindsight/compose.yaml:23–34` leaves native LLM tracing at upstream defaults. In the evaluation venv, Hindsight 1.2.1 reported `llm_trace_enabled=True`, `llm_trace_max_chars=50000`, `llm_trace_retention_days=1` and `llm_trace_delete_with_document=False`. The pinned engine installs a per-bank database recorder in `hindsight_api/engine/memory_engine.py:3545` and tests the document-deletion flag at line 11670. The proxy's lack of prompt logging does not cover these native traces. Set `HINDSIGHT_API_LLM_TRACE_ENABLED=false` in the shipped configuration and validate the effective value. Exercise synthetic retain/delete with a content marker and verify native trace storage, retention and restore handling separately from operational counters.

2. **P1 — The real app rejects the native activity probe.** The gateway sends its service bearer in `deploy/hindsight/alfyai_admission.py:72–80`. The global gate in `src/hooks.server.ts:55–76,359–429` requires a session cookie for this path, so the request returns 401 before `src/routes/api/internal/memory-admission/+server.ts` can authenticate it. All documented modes therefore run at one. The six-call recorded burst used a different HTTP activity server. Allow the exact GET route through the session gate to its existing bearer check. Exercise the normal app entry point with valid bearer, missing/wrong bearer and cross-process foreground start/finish, and measure the gateway during overlap.

3. **P1 — Rotating the active key breaks existing users' edits and removals.** `src/lib/server/services/memory-profile/curation-runner.ts:144–151,364` compares the stored binding with one freshly calculated from the active key for every action. A bank bound at v1 therefore fails with `native_binding_changed` when v2 becomes active even if v1 remains in both keyrings. `hindsight-client.ts:320–340,369–384` already resolves the recorded hash with retained keys. Use that binding consistently for actions, source delivery and cleanup. Exercise Add/Edit/Remove on a pre-rotation bank, a new bank, outstanding work and cleanup with real persisted hashes.

4. **P2 — First-action bank creation has an untracked erasure window.** `curation-runner.ts:153–165` creates/configures a native bank before committing its binding. Concurrent reset/erasure or process loss between those operations can leave an empty remote bank outside `delivery-job.ts:183–185`'s cleanup selection. The Add flow first submits user text after this step, so this particular gap establishes orphaned bank/config metadata. Persist a fenced binding before remote configuration, as source delivery already does at `delivery-runner.ts:245–265`. Exercise reset and recovery between configure and acknowledgement.

5. **P1 — Private destination restrictions are missing on the native path.** The admin-editable `HINDSIGHT_URL` is only trimmed in `src/lib/server/config-store.ts:1111–1113`. `hindsight-client.ts:59–76` accepts arbitrary HTTP(S) hosts and sends a reusable tenant bearer with the first capability request, before it can verify the response. `deploy/hindsight/alfyai_admission.py:43–52,74,83` also accepts arbitrary HTTP(S) model and activity destinations from deployment configuration. This concerns privileged configuration errors and operator-controlled destinations. I found no browser-controlled forwarding URL on the reviewed paths. Pin allowed private service destinations in deployment-owned configuration and validate the final resolved target before credentials or content leave the process, including for stored bindings. Cover invalid/public destinations through a capture-only transport. Keep explicit support for the private Docker host gateway. The curation sender already checks its configured private gateway and refuses redirects.

6. **P2 — The foreground signal can stall the event loop on database contention.** `request-activity.ts:23–41,52–54,67–75` performs synchronous SQLite writes for start, renewal, finish and every status poll. The shared connection in `src/lib/server/db/index.ts:9` waits up to ten seconds for a writer. The catch for failed tracking runs only after that wait. An auxiliary poll that merely checks whether chat is active can itself block chat and unrelated requests. Use a short, independent contention budget for best-effort activity writes and a read-only status query over unexpired leases. Test with a second connection actually holding the writer lock and measure foreground progress. A per-process failure cooldown still cannot assure other app processes' readers that the originating process is healthy.

7. **P2 — Reserved database passwords fail with the documented encoding procedure.** `deploy/hindsight/compose.yaml:8,24` supplies the same string as the literal Postgres password and as URI userinfo. `deploy/hindsight/README.md:8` instructs operators to percent-encode reserved characters. I ran Compose config with two temporary synthetic bundles. The URL-decoded password matched the database password for an alphanumeric secret and differed for one containing a percent-encoded at-sign. Use an explicitly URL-safe generated raw password or provide separate properly encoded connection configuration. Generated master key JSON survived the same Compose round trip.

## Evidence and limits

- I reran the eight Python unit tests successfully and checked the scratch source checkout at `9fb28dbd724dc1ce4da7cb4c49008e601db76c5f`. The Dockerfile checks out and verifies that revision before installing it. Its recorded commit and the capability endpoint establish source-build identity for a trusted deployment. The endpoint reads a build stamp and returns a schema-derived hash. It cannot distinguish another database restored at the same address with the same keyring. Container build/start and coordinated database restore still need independent evidence.
- The tenant verifier parses a canonical opaque UUID, checks a fixed-length HMAC with constant-time comparison, and invokes the native schema migration only after verification. Native tenant discovery filters for canonical schema names. Its credential is a versioned bearer HMAC. The recorded isolation fixture shows distinct data at the same bank ID for two tenants, refused cross-tenant fact mutation, and a deletion in B that preserved A. Projects within one tenant depend on AlfyAI's authenticated scope checks at `revisions.ts:31–71,183–225`. Automatic schema provisioning for an authorized native account works independently of account enrollment. New accounts still default to legacy at `src/lib/server/db/schema.ts:3200`; the smoke sets authority directly. The ordinary account creation/rollout path remains Task 7 evidence.
- `native-live.integration.test.ts` exercised two app delivery jobs, publication and native recall using synthetic source revisions. It asserted both EN/HU values in serialized list output and the English value in direct client recall. It does not assert the Hungarian value in app-admitted recall or exercise account creation, chat submission, curation or the public action API. The recorded isolation and model burst results were reviewed. My independent GET to the scratch health endpoint could not connect, including after sandbox escalation. I did not restart either service.
- The installed gateway has an atomic, process-local limit and returns 429 on contention, with no waiting queue after its activity probe. The fixed upstream ignores a request-supplied destination. One replica is required. Existing admissions can drain at six during a downshift. `alfyai_admission.py:83–88` frees a slot when an upstream connection times out or fails, without knowing whether the provider stopped generation. The demonstrated ceiling covers open gateway requests. Bound actual provider work under slow/abandoned requests using backend-side measurements, including native retries and curation together. Native's one-second retain HTTP admission wait does not set its model-semaphore wait or its asynchronous operation deadline. Task 8 still needs fairness, end-to-end overlap, outage/restart, restored erasure fences and sustained growing-bank latency.
- Restore and release remain on hold. Keep the existing job engine and narrow auth/admission extensions. These repairs do not require an additional service, model, scheduler or extractor. No production settings, services or user data were used or changed in this review.
