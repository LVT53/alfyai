# Paired observation and linked-fact diagnostic

On the same 60 scope-compatible questions, a repeat using the app's exact observation text passed **48/60**. Replacing those observations with the exact already-linked raw native facts passed **52/60**. Linked facts recovered seven answers and lost three. The original integrated result remains 50/72 overall and 47/60 on this subset. [Primary report](../README.md) · [Paired summary](summary.json) · [All 120 manual judgments](manual-grades.json)

Both passed 45 pairs and both failed five. All 120 generations returned normally through the local Flash Next alias. The experiment reconstructs each check from its own archived accepted generation, retains the actual app ranking and scope, and verifies each linked fingerprint against its earlier accepted source's exact fact text and bank. Deduplication uses native fact identity. Both arms use the same `content` field and bullet layout, frozen date, Dublin time zone, original project, unchanged question and shared answer function. Pair order alternates by fixture index. Both arms fit the 8,000-token application row-text budget, with maxima of 768 and 1,183 estimated evidence tokens. ## What the paired evidence shows

- Raw-linked answers recovered the outbound/return distinction in p01 and p03 and the p06 itinerary return. The observation could be only a date span, while its raw supporting fact says which date is the home return. Raw facts also recovered p01's location answer without inventing workshop dates, and p06's departure without inventing the course schedule or where the user currently was.
- p03's current-device answer repeated the unsupported everyday-use habit in the observation arm. The raw-linked arm received the old Prusa's actual habit and the later swap to the Creality as separate facts, then answered without carrying over the habit. In p05, the observation text correctly said the user helped choose accessories. The observation answer changed that to choosing a device and the raw-linked answer omitted the unsupported detail.
- Raw-linked regressed on p02's reply format, p05's copy approval and p06's Cedar style. In p02, raw evidence exposed both the superseded numbered-list preference and its dated replacement. The answer chose numbered items. In p05, the raw evidence explicitly said the copy was approved, and the answer said only that it was finished. In p06, the model said the current request was outside Cedar despite the fixture and answer payload both putting it in Cedar.
- Both representations still triggered unsupported workshop dates or attendance in p03, p04 and p05, conflated fictional and reviewer sources in p04, and omitted the approved-copy status in p06. The linked facts preserved the missing distinctions in these cases, so correct evidence alone did not resolve them.
- The observation repeat changed five verdicts relative to its original generation, with three newly passing and two newly failing. The four-point net paired gain reflects this model, layout, and dataset. It cannot explain the full historical standalone gap. Earlier standalone recall independently ranked observations and world facts and added original chunks, explicit event timestamps and source-fact objects. Its 58/60 scope-compatible score came from that different input and extraction configuration. [Earlier benchmark report](../../prior-findings/larger-benchmark.md)

## Evidence-format candidate

The existing immutable publication already stores exact linked raw fact IDs and texts in `sourceFingerprintsJson`. `readPublishedMemory` admits a row only when its exact supporting facts still pass current source, bank and revocation checks. The generation stores a single effective date per observation in `updatedAt`. Its fingerprint entries do not store each raw fact's individual effective assertion date, including dates verified for an accepted correction replay. [Publication and read checks](../../../../../src/lib/server/services/memory-profile/publication.ts)

A small next experiment is to keep accepted observation text as the default and attach bounded, deduplicated linked facts when evaluating date or ownership fidelity. Use the exact immutable row fingerprints that survive the existing final admission transaction, under the same scope, ranking, generation and recall budget. If the experiment needs per-fact dates, persist the effective dates alongside the fingerprints during publication and use only dates present in that accepted generation. Apply the same erasure, curation and source revocation tests before considering a product change. The supported candidate uses no live staging acknowledgements, original chat chunks, alternate ranker or new semantic checker. The mixed pair outcomes do not justify a blanket replacement of observations.

## Reproduce

From the repository root, use the same synthetic Flash Next loopback bridge as the primary run. Run `/opt/homebrew/opt/node@22/bin/node --import tsx docs/plans/hindsight-memory/integrated-native-benchmark/paired/run.ts p01` for each profile through `p06`, with `/tmp/alfyai-integrated-memory/paired` present. The script reads the six fixed primary archives and checkpoints each completed pair. Each record holds archive and runner hashes, evidence hashes, exact ranked evidence, linked IDs and source dates, and returned answers. Run `python3 docs/plans/hindsight-memory/integrated-native-benchmark/paired/review.py` to verify the records and recompute the summary. [Synthetic provider trace](model-calls.jsonl.gz)
