## What is already demonstrated

The final decision replaced the evaluator's abandoned “leave conflicts unresolved” rule. Do not revive those superseded failures as current blockers.

[Bounded updates](bounded-update-results.md) established per-document acknowledgement and bounded native mutation; the 10/100/300-claim size checks bypassed extraction and disabled observations, so they do not prove production current-list semantics or latency. Existing native correction/removal probes remain evidence for the curation primitive, not proof that the new plain-text editor correctly derives every mixed change/removal request.

The prior 69/72 versus actual AlfyAI 37/72 tool /32/72 passive benchmark is evidence of useful recall improvement, not proof that every visible row, source link or history record is correct.

## Owning-source evidence

- Pinned `hindsight-docs/docs/developer/api/memories.mdx`: list includes invalidated records by default; state filtering is needed; native timestamps have different meanings; text `q` is substring inspection, with Recall recommended for production search. The history endpoint explicitly describes derived-observation refreshes.
- Pinned `hindsight-api-slim/hindsight_api/engine/memories/pg/reads.py`: bank-scoped reads, document filtering, offset pagination. Its documented cursor is a position, not a snapshot. Concurrency and completeness must be tested against the actual read representation.
- [Correction recovery](correction-recovery-results.md): answer precedence works without deleting all earlier raw evidence; generated observations can invent physical historical transitions. It explicitly disclaims universal paraphrase discovery, large-bank recall completeness and production transaction guarantees.
- [Readiness matrix](replacement-readiness.md): A1–A5 remain implementation/release acceptance, not completed UI integration tests.

## Tests that belong during implementation, not another Hindsight feasibility bench

Actual transactional publication and multi-worker crashes; on/off and incognito enforcement in every read/write path; Profile reset/erase/export across personal/project banks and late queues; migration and backup policy; source-message navigation/load/highlight and ownership; stale-edit UI, pending/failure/retry and source-unavailable states; EN/HU, accessibility, focus, long content, reduced motion and mobile; Feature Guide updates; realistic local-model latency/backlog/cost and larger-bank recall. Test these against real application routes/workers once implemented. Do not claim scratch JSON ledger results prove production database transactions.

Error styling, navigation layout and animation do not require Hindsight calls. Removing the duplicate Manage screen reduces UI scope and preserves Profile ownership; it does not eliminate the backend tests for those existing settings.

## Decision

The UI direction is recorded and ready to guide implementation planning. **Not yet justified: “all Hindsight-facing design assumptions are solved.”** First qualify the current read view, editor omission semantics, provenance-backed history and new bank composition with the bounded existing mechanisms. If those pass, no additional open-ended UI-feature feasibility investigation is identified by this audit; proceed only on owner implementation authorization, then complete application/release gates.
