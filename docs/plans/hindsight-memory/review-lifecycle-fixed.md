# Independent lifecycle re-review

**Request changes.** Five fresh synthetic probes reproduced four lifecycle defects and one job API gap. Existing regressions cover the original interleavings. Source identity changes, terminal Edit failure and deliberate deletion during compensation still break required outcomes.

## Findings

1. **P1 · A terminal Edit failure can silently remove previously accepted information.** The Edit applies a native PATCH, then detects an unexpected extra fact in the staged delta and returns `memory_edit_readback_mismatch`. The failure handler marks the intent rejected, deletes the staged delta and clears cleanup without restoring the original native fact. The accepted snapshot still shows the original kayak until an unrelated Add publishes. That successful Add leaves only chess and the bicycle. Persist compensation before releasing the hold and keep the failed Edit rejected. The compensation must restore accepted facts and verify rebuilt descendants when native writes already began. [Terminal failure handler](../../../src/lib/server/services/memory-profile/curation-runner.ts#L413), [dirty marker and native PATCH](../../../src/lib/server/services/memory-profile/curation-runner.ts#L855), [publication hold](../../../src/lib/server/services/memory-profile/publication.ts#L136)

2. **P1 · A verified Remove can still publish the removed detail under a new observation identity.** The fixture invalidates the kayak raw fact, preserves the bicycle and independently supported chess, and adds a new native observation “green kayak and I play chess.” backed only by the accepted chess fact. The final checker receives only the bicycle observation. Its stub would refuse any supplied observation repeating the kayak. Strict raw-fact admission subsequently accepts the new chess-backed row, the operation reports applied and the normal list displays the removed kayak. Verify the bounded diff between the settled candidate and the accepted snapshot. Include new or changed rows even when their identity and support moved outside the original set, or keep that candidate held when the diff exceeds the budget. [Affected observation selection](../../../src/lib/server/services/memory-profile/curation-runner.ts#L85), [strict publication](../../../src/lib/server/services/memory-profile/publication.ts#L209)

3. **P1 · Deliberate source deletion can strand the whole bank after a cancelled Edit.** The probe switches Memory off while the first PATCH is returning, deletes the affected original message through the production revocation and cleanup path, and confirms that its native source cleanup succeeds. On enable the action fails with `memory_edit_restore_source_changed`. Restoration requires every original source to still be accepted, while the rollback flag indefinitely blocks unrelated Add with `memory_action_pending`. Keep the Edit rejected, honor the newer deletion, restore only currently authorized survivors, and clear the hold after verifying the remaining native result. A retry of the saved operation cannot make a deliberately revoked source accepted again. [Restore fence](../../../src/lib/server/services/memory-profile/curation-runner.ts#L477), [action admission](../../../src/lib/server/services/memory-profile/curation-actions.ts#L106), [publication hold](../../../src/lib/server/services/memory-profile/publication.ts#L136)

4. **P1 · A successful changed resend can sever prior Remove intent for the next unchanged resend.** Start with an accepted Remove of green kayak, deliver a changed revision which adds only chess, then resend that revised text identically. The middle revision succeeds and the final checker receives the original Remove. The next revision is sent as full text. No checker payload for it contains the saved Remove, despite correct predecessor identities and common lineage. The conservative fixture rejects the repeated green fact, and previously accepted chess is absent from the list after the failed resend. The earlier intent is read for verification of the middle revision but its successful settlement stores no continuity for the next predecessor. Keep the ordered intent chain across successful revisions. An unchanged resend must preserve accepted facts and their dates. Exercise a newer deliberate conflicting assertion across subsequent identical resends as well. [Changed settlement](../../../src/lib/server/services/memory-profile/curation-runner.ts#L1322), [immediate-predecessor intent lookup](../../../src/lib/server/services/memory-profile/curation-runner.ts#L985), [earlier edits used only for final verification](../../../src/lib/server/services/memory-profile/curation-runner.ts#L1396), [full-text unchanged retain](../../../src/lib/server/services/memory-profile/delivery-runner.ts#L352)

5. **P2 · The new `prepareCheckpoint` signature accepts asynchronous work that can escape the attempt fence.** A callback returning a promise satisfies the public `unknown` return type. The ledger calls it with the real transaction and only then rejects its promise. The probe captures its query builder before returning the promise. After a subsequent successful verdict it resumes and writes a domain column, even though the checkpoint was rejected and the attempt settled. The production repair caller is synchronous and passes its success/rollback tests. Narrow the callback to a synchronous serializable checkpoint shape and cover the type boundary. Reject obvious async callbacks before invocation and observe accidental returned rejections. An internally scheduled closure is outside the documented transaction contract. [Public callback type](../../../src/lib/server/services/jobs/types.ts#L142), [callback invocation and ownership checks](../../../src/lib/server/services/jobs/ledger.ts#L735), [promise check](../../../src/lib/server/services/jobs/ledger.ts#L76)

### Remaining defects

1. **P1 · An identical resend before the first delivery completes silently drops the assertion.** The probe records an eligible chat assertion through the real completed-turn entry, leaves its first delivery queued, revokes that message through the production edit path and accepts an identical successor. The predecessor has never submitted to native and has no acknowledged facts. `unchangedSourceFacts` returns an empty array before checking accepted evidence. Delivery treats that array as a verified empty snapshot and skips retain entirely. The real successor job reports succeeded and Memory stays empty. Distinguish an accepted zero-fact snapshot from an assertion that has never been processed. Admit the still-current assertion with its original date and resolved context when the predecessor never authorized any native writes or curation. Preserve the existing verification fence for ambiguous submitted predecessors and honor acknowledged removals. [Empty acknowledged facts](../../../src/lib/server/services/memory-profile/curation-runner.ts#L1194), [retain decision](../../../src/lib/server/services/memory-profile/delivery-runner.ts#L372)

2. **P1 · A deleted root still strands cancelled Edit recovery when a remaining reply depended on it.** The probe switches Memory off during native re-retain of a surviving “Yes.” reply under a dirty Edit, then deletes the original root. After enable, the cancelled Edit rebuilds that reply without the root and the native fixture correctly returns no fact. The rollback checker receives the old child fact and no `source_assertions` or sanitized prior context to establish that the child depended on the withdrawn root. The fixture declines to certify this loss. The real action remains cleanup-pending with `memory_dependency_check_rejected`; an unrelated Add is refused. The rollback shares repair execution with ordinary deletion, whose verifier receives the child's original assertion and sanitized context. Carry that evidence into combined compensation whenever withdrawal changes what qualifies for preservation. Settle overlapping repair work for the same family and verify an independent claim in the surviving reply still remains. This probe establishes the omitted input and stuck state under a conservative checker response. Actual local-model acceptance of the combined intent remains unverified. [Compensating repair](../../../src/lib/server/services/memory-profile/curation-runner.ts#L681), [deletion checker inputs](../../../src/lib/server/services/memory-profile/curation-runner.ts#L1769), [assertion and prior context produced by repair](../../../src/lib/server/services/memory-profile/dependency-repair.ts#L519)
