## Source findings

1. **The detail card can misstate a memory’s source.** A manual memory shows an empty Conversation card. The native API returns explicit `origin: "manual"` for an Add with verified lineage. The detail template unconditionally renders Conversation and only fills its body from chat sources. The existing English and Hungarian “Added by you” labels are unused. Follow the approved provenance treatment using the explicit origin field. Omit that card for an unknown origin without sources. When editing a source message leaves the original quote unavailable, describe the source as unavailable. The chat can still exist, as the carried-source regression illustrates. [Native detail](../../../../src/lib/server/services/memory-profile/native-read.ts#L363) · [Detail template](<../../../../src/routes/(app)/knowledge/_components/MemoryDetail.svelte#L46>) · [Carried-source fixture](../../../../src/lib/server/services/memory-profile/curation.integration.test.ts#L3083)
2. **One initial list failure produces two copies and two Retry buttons.** After a failed list read with no accepted page, the coordinator sets a retryable ErrorMessage and the child list renders the same localized failure with its own Retry handler. The child retry debounces a fresh search while the shared retry repeats the failed load. Render one recoverable failure with the shared component and keep the empty state for a successful empty response. [Coordinator](<../../../../src/routes/(app)/knowledge/_components/KnowledgeMemoryView.svelte#L252>) · [List template](<../../../../src/routes/(app)/knowledge/_components/MemoryList.svelte#L48>)
3. **Cancel Add has no correct keyboard return target.** Add replaces the list, and Cancel uses the same Back path that only looks up the last remembered row. A fresh visit with no opened row has no target. A visit that opened an unrelated row can send focus there. Back after removal has the same missing-target case once the row disappears. Give Add and removed/stale rows a stable visible return target and keep the existing exact-row restoration when available. [Back and Add](<../../../../src/routes/(app)/knowledge/_components/KnowledgeMemoryView.svelte#L333>) · [Editor cancellation](<../../../../src/routes/(app)/knowledge/_components/KnowledgeMemoryView.svelte#L748>)
4. **An open editor can offer a Save that silently does nothing after Memory turns off.** Once the account or refreshed list says off, the coordinator's `disabled` guard prevents a send. The open editor and Remove confirmation receive busy/stale flags with no general off flag, so their action buttons can still appear enabled. Exercise a second-tab Memory toggle with Edit or Remove still open. Keep the controls and feedback consistent with the authoritative state. [Mutation guard](<../../../../src/routes/(app)/knowledge/_components/KnowledgeMemoryView.svelte#L538>) · [Editor and confirmation props](<../../../../src/routes/(app)/knowledge/_components/KnowledgeMemoryView.svelte#L748>)
5. **Reduced motion removes the hover animation and leaves its 2px displacement.** The row rule applies `translateX(2px)` under hover while the reduced-motion block disables only transitions and animations. The approved row treatment suppresses this decorative movement. Preserve the color feedback in reduced motion. [Row hover](<../../../../src/routes/(app)/knowledge/_components/memory-replacement.css#L153>) · [Reduced-motion rules](<../../../../src/routes/(app)/knowledge/_components/memory-replacement.css#L406>)
