## Existing retrieval models

Final production preparation is held while qualifying the owner's request to reuse the existing embedding and reranking services. The initial staging configuration uses local ONNX embeddings and Flashrank, with the existing local Qwen generation model. It provides a baseline for app behavior.

Both canonical app environment files configure the existing Qwen embedder at 1024 requested dimensions and batch size eight, and the BGE reranker at up to eight texts. Both services returned HTTP 401 on an independent unauthenticated `/info` request. The pinned native TEI adapters require that endpoint and provide no bearer setting. They send plain TEI request bodies, without an embedding dimension or truncation override. Native PostgreSQL also rejects vectors above the 2000-dimension limit for its HNSW index. Test the actual authenticated provider response and model dimension before choosing a binding, then qualify retain, consolidation and recall against a fresh staging database with that binding. Existing populated vector tables cannot be resized by the native startup migration. [Pinned embedding transport](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/embeddings.py) · [Pinned reranker transport](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/engine/cross_encoder.py) · [Vector storage limits](https://github.com/vectorize-io/hindsight/blob/9fb28dbd724dc1ce4da7cb4c49008e601db76c5f/hindsight-api-slim/hindsight_api/migrations.py)

The authenticated provider probes returned 1024 dimensions through the existing OpenAI-compatible embedding endpoint and 2560 through plain TEI without an explicit dimension. The existing reranker returns the TEI array shape and rejects the alternate Cohere-style request body. The reviewed Compose override preserves both host services and adds a private authenticated transport for the selected Hindsight process, with request and response limits and a one-request cap per GPU endpoint.
