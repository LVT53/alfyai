## What I built, per step

### Step 1 · what this chat has, as insertable blocks

- **`src/lib/shared/artifacts/chat-blocks.ts`** (client-safe): the listing's wire types (`CanvasChatBlocks` = `{ files, apps, maps, charts }`, each item `{ key, at, … }`), `CHAT_BLOCKS_PER_KIND` (12), `CHAT_BLOCKS_SCAN_MESSAGES` (200), `emptyChatBlocks()`, and the **one file-id convention**: a produced file's `fileId` is its chat-file id, an attached file's is `artifact:<artifactId>` (`attachedFileId`, `fileBlockSource`) — the same `artifact:<id>` the panel already uses as an attachment's item id, so opening one file from a message and from the board is the same panel item.
- **`services/artifacts/chat-blocks.ts`** → facade `listCanvasChatBlocks({ userId, artifactId, conversationId? })`. The board is resolved through THE scoped read (`readScopedArtifactRow`), must be a Canvas, and the conversation it lists is the board's own, re-checked against `getArtifactOwnershipScope` before any helper that takes a bare conversation id runs. `null` = "no such board": a stranger's board, a missing id, an incognito chat's board read without/from another chat and a non-Canvas all answer alike, and the route's 404 is byte-identical. Every source is one the family already reads through: `listConversationGeneratedFiles` (produced), `listMessageAttachments` (only `source_document`), `listArtifactsForConversation` (Apps), `listMessageWindow` over the newest 200 messages (maps from finished `map_route` tool calls; charts from assistant replies through the chat's own `classifyMarkdownBlocks`, so a fence and a bar-column table both count). Newest first, 12 per kind, a chart repeated by several replies once. Every item is checked against its block's shared schema (`BLOCK_DATA_SCHEMAS`), so nothing is offered that the next save would drop (a malformed route, a chart past 100,000 characters). The service queries no table itself (the containment suite's PART B guard is untouched).
- **`GET /api/artifacts/[id]/chat-blocks?conversationId=`**: thin (`requireApiUser`, `{ ok: true, files, apps, maps, charts }`, 404 `{ ok:false, reason:"not_found" }`), and `fetchCanvasChatBlocks(artifactId, conversationId?)` in `client/api/artifacts.ts`.
- The route is keyed by the **board's id** (with `?conversationId=` for an incognito chat, ruling 51), not the chat's: "the board's own conversation" is then a fact of the row, and the scope is the same one `GET /api/artifacts/[id]` uses.

## Deviations from the spec / brief, and why

1. **The blocks are not nodes that compose `NodeShell`** (S3-B's hand-off pattern): the wrapper (`LazyNode`) owns the shell and the block modules are content + a shell dress. Reason: the bundle (above), and it is a stronger form of "new blocks load when they mount": an edge can attach to a block before its code has arrived. `nodes/{File,App,Map}Node.svelte` exist and are named as the brief says.
2. **The listing is keyed by the board's id**, not the chat's (the brief's "another user's chat … with its id" reads the same through the board's conversation).
3. **A block from the chat is not always at the view's centre**: at the centre when that ground is free, else the nearest free ground (a note keeps the centre + stagger).
4. **`fileId` carries two kinds** (`artifact:<id>` for an attached file); the spec's text names chat files only.
5. **`section: "chat"`** in `BlockMeta`, and `insertableEntries()` excludes it; `defaultDataFor` returns `null` for the three; the spec's registry row for `file` says "FileTypeIcon + the shared viewer" — done through the panel's open callback, no viewer of its own.
6. **A chart from the chat takes the chart's title as its label** (not in the brief).
7. **S3-B's menu-keys spec was changed (8 lines)**: it focused a row straight after the menu appeared and lost that focus to the popover's own first-focus timer under CPU load. Pre-existing: with S3-B's original `InsertMenu` restored, the same sequence failed 3 in 10 under 10 busy loops (and 2 in 10 with mine); it failed once in my first full run. The spec now waits for the popover's focus first.
8. `tests/e2e/artifact-canvas.spec.ts`: its "unsupported block" was a map; a map is drawn now, so it is a photo (their own slice: S3-R2 will need to change it once photos draw).

### A paragraph for `AGENTS.md`'s Artifacts section (I did not touch it)

> **Blocks from the chat (Wave 3).** A Canvas can hold what its own chat made — a produced or attached file, an App, a route the `map_route` tool returned, a chart a reply drew. `GET /api/artifacts/[id]/chat-blocks` (a thin route over `services/artifacts/chat-blocks.ts`, facade `listCanvasChatBlocks`) lists them, newest first, 12 of each, through the same scoped read as every artifact route (an incognito chat's board answers only a read that names that chat; a stranger's board, a missing id and a non-Canvas answer alike) and only through services that already own the data (`listArtifactsForConversation`, the file-production read model, `listMessageAttachments`, `listMessageWindow`, and `classifyMarkdownBlocks` for charts — the chat's own reading); every item is checked against its block's shared schema so nothing is offered that a save would drop. A File block's `fileId` is a produced file's chat-file id or `artifact:<id>` for an attached file (`shared/artifacts/chat-blocks.ts`). The Insert menu's "From this chat" is one lazy component (`canvas/chat-blocks/`) that builds a route's label client-side with the chat's own grammar (`buildToolActivityItem`). The File, App and map blocks are drawn by `LazyNode`, which owns the shell and loads only the content (`nodes/{File,App,Map}Node.svelte`: content plus a `<kind>Shell` function): **a content module may not import `NodeShell`, the flow library or the registry**, or the bundler splits the shell out of the editor's chunk; `npm run check:artifact-chunks` allows the `canvas/nodes/` and `canvas/chat-blocks/` lazy entries. An App block runs in the panel's own `AppFrame` (sandbox `allow-scripts allow-forms`, ruling 58) with the App's own storage and `nodrag nowheel nopan`; a File block opens through the panel's `onOpenItem`, which `DocumentWorkspace.svelte` hands to the host's own `onOpenDocument`. A block picked from the chat is placed on free ground (`placeBesideBlocks`), not staggered like a note.
