# Feature 2 · Artifacts — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking. **Read this file first, then your slice's file.** Each `slice-*.md` is a self-contained plan for
> one agent.

**Goal:** Ship "Claude at home" item 2 — a family of five artifact types (Document, App, Canvas, Slides, File)
that live **beside** the conversation, keep their state, and that both the user and Alfy edit over time: one
card in the chat, one panel next to it, one comments layer, one version history, and one export path.

**Architecture:** Artifacts are a **new family on the existing `artifacts` backbone**, never a parallel document
store. One new `artifacts` type value (`'artifact'`), three new tables (`artifact_versions`,
`artifact_comments`, `artifact_kv`), and a new deep module `src/lib/server/services/artifacts/` behind one
facade. The panel is `document-workspace/DocumentWorkspace.svelte` **rebuilt in place** (three callers already
use it: chat, knowledge, project files); its content area becomes type-aware and every type's editor is a lazy
`import()`. The card is one `ArtifactCard.svelte` in chat, with `FileProductionCard.svelte` demoted to the
`file` body rather than a second card. Alfy addresses a Document by **block id written into the Markdown**
(`<!--b:id-->`) and every patch carries the hash it last read, so an edit to a block the user changed after
that read is **refused per op** instead of overwriting the user's words. Apps are generated by a **separate
model call with thinking off**, verified for factual content, then served from an authenticated route into
`<iframe sandbox="allow-scripts">` with a `postMessage` storage bridge onto `artifact_kv`.

**Tech Stack:** SvelteKit + Svelte 5 runes, Drizzle ORM on better-sqlite3, Vercel AI SDK tools with Zod,
Tailwind with `src/app.css` tokens, Lucide via `@lucide/svelte`, Tiptap 3.31.3 (Document), `@xyflow/svelte`
1.7.0 + `perfect-freehand` + `html-to-image` (Canvas), Vitest, Playwright, Biome, Fallow.

**Spec:** [`docs/plans/claude-at-home-2-artifacts-spec.md`](./claude-at-home-2-artifacts-spec.md) — **§2's

## Global Constraints

Copied verbatim from the spec, the ADRs and the handoff; every task in every slice implicitly includes these.

- **Node 22 only.** `export PATH=/opt/homebrew/opt/node@22/bin:$PATH` on every npm/npx/vitest/playwright call.
  Node 26 breaks `better-sqlite3`.
- **"Artifact" is never shown in the UI** (ADR-0066). UI names and their Hungarian: Document / **Dokumentum**,
  App / **Alkalmazás**, Canvas / **Tábla**, Slides / **Diasor**, File / **Fájl**. Code, tables, routes and
  file names may say artifact; user-visible strings, `title` attributes, `aria-label`s and error copy may not.
- **One user, forever. No sharing, ever.** Do not design for it, do not leave a seam "for later", do not list it
  as a future option (spec §2.16, owner: "a whole different can of worms").
- **Your words win.** A patch addressed to a block the user changed after Alfy last read it is **refused**, per
  op, with a visible notice; the other ops still apply. Never silently overwrite, never "last writer wins".
- **Block ids persist in the Markdown** as `<!--b:xxxx-->` (≈17 chars/block, +14%). Minting/absorbing happens
  **immediately after parse — before hashing, snapshotting or rendering**. The prototype's own bug: ids minted
  lazily left the first read looking at a document with no identity at all, so every patch was refused.
- **Apps are generated with thinking OFF**, on a **separate call** from the chat turn, with the App contract as
  the prompt, and facts are verified before the card appears. The App contract forbids agentic behaviour: the
  answer is the app and nothing else.
- **Canvas geometry is board coordinates.** Any pointer-capturing overlay is sized from the **visible board
  rect** `[-pan/zoom, (-pan+paneSize)/zoom]`, never from the board's own box. Frame children carry `z-index: 1`;
  both overlay layers claim `z-index: 2`.
- **Heavy editors are lazy.** Nobody pays 147 kB gzip for a Document they never opened.
- **i18n:** every new string exists in English and natural Hungarian in the same commit, in
  `src/lib/i18n/artifacts.ts`, with the module registered in `I18N_MODULES` and its prefix in
  `AUDITED_PREFIXES` (`src/lib/i18n.test-helpers.ts`). `chat.` as a whole is **not** audited, so a new
  `chat.artifacts.*` namespace is invisible unless the prefix is added too.
- **Icons:** Lucide via `@lucide/svelte` only; never inline `<svg>` for an icon. Colours and spacing from
  `src/app.css` tokens, never hard-coded. (Verified against `@lucide/svelte` 1.17.0: the mockup's `checks` is
  `list-checks`, `chart` is `chart-column`, `shape` is `shapes`.)
- **Boundaries** (AGENTS.md): routes are thin adapters; browser fetches in `src/lib/client/api/`; runtime config
  through `env.ts` → `config-store.ts`; persisted message metadata in `messages.ts`; model tools in
  `normal-chat-tools/` with their usage guidance in the tool interface (ADR-0055); the panel is not a second
  modal viewer for surfaces that already have one.
- **Schema:** every new table needs a Drizzle migration **and** a `_journal.json` entry; `npm run check:migrations`
  must pass; every new user-keyed table must be registered in
  `src/lib/server/services/account-lifecycle/user-scoped-tables.ts` or the completeness guard in
  `account-lifecycle.test.ts` fails the suite.
- **Every user-scoped artifact query takes `getArtifactOwnershipScope`**
  (`src/lib/server/services/knowledge/store/core.ts:141`) or pins itself to one conversation, or
  `tests/cross-cutting/incognito-artifact-containment.test.ts` PART B fails the day the file is written.
  **Adding an `ALLOWED_WITHOUT_SCOPE` exemption to make it green is forbidden** — the guard's second test
  deletes stale exemptions on purpose.
- **Commits:** small, focused, explaining *why*. Stage by explicit path. **Never** bare `git stash`. End every
  commit message with `Co-Authored-By: Claude Code <noreply@anthropic.com>`.
- **Never push and never deploy to production** without the owner's explicit go-ahead. Slices land as local
  commits; the orchestrator reviews and merges.
- **`npm run lint` is broken** by nested worktrees (biome finds nested roots under `.claude/worktrees`). Lint
  `npx biome check src scripts tests` instead and say so in reports.

## Review Focus

The six failure modes the spec implies but no single task's happy path exercises. Each is pinned by a test in
the slice named next to it.

1. **A block id that does not survive a reload.** Alfy creates a Document, the user reloads, Alfy patches it
   again: ids must be the same ids and the patch must address them. A load path that mints ids after hashing,
   or that re-mints on every parse, makes every second-turn patch a refusal — and it fails *silently*, because
   the refusal is a legal outcome (Slice 1, Task D2 + the reload E2E in Task D8).
2. **A refusal that takes the good ops down with it.** Patch 3 ops, the user edited one: `{applied: 2,
   refused: [{blockId, reason}]}`, the two are applied, the refused one is named in the UI, and Alfy's own next
   message says what it left alone (Slice 1, Tasks D3/D5).
3. **Ownership and incognito across three new tables.** A version row, a comment row and an `artifact_kv` row
   are as sensitive as the artifact they hang off: none may be readable from outside the artifact's own
   conversation, none may appear in the panel list, the Knowledge library or workspace search, and the
   per-table erasure/no-survivor expectations must hold (Slice 0, Task S4; repeated per type).
4. **An App that can reach the parent.** The served HTML must never run same-origin: `<iframe
   sandbox="allow-scripts">` **without** `allow-same-origin`, a strict CSP on the serving route, and
   `window.alfy.storage` implemented as a `postMessage` bridge with an origin check and a hard cap on stored
   bytes — no privileged global, no `localStorage`, no network (Slice 2, Tasks A2/A3).
5. **Canvas traps that fail silently.** Lowercase Svelte Flow events, library-side `addEdge`, no `snapToGrid`,
   `selectionMode` as an enum, the `.svelte-flow__selection-wrapper` pointer-events overlay, portal content
   that cannot be styled from its parent, and a pad sized to the board box instead of the pane. Each is listed
   with its symptom in Slice 3's trap table (Slice 3).
6. **Cost that nobody sees.** Apps, Slides and Canvas diffs cost extra model calls; the existing cost display
   must show them, and the artifact count button must not appear in a chat that has made nothing (Slice 0's
   surfacing rule; Slice 2 and Slice 5 for the accounting and the guidance).

## Slice order, dependencies and parallelism

```
Wave 1   Slice 0  (the spine)                                  — everything imports it
Wave 2   Slice 1  (Document)      ∥   Slice 2  (App)           — disjoint except three append-only files
Wave 3   Slice 3  (Canvas)                                     — needs 0's panel, 2's sandbox for App blocks
Wave 4   Slice 4  (Slides)                                     — needs 0's panel, 3's export/present plumbing
Wave 5   Slice 5  (Alfy's side: prompt guidance, evidence, project bundle)
Wave 6   Slice 6  (first-open tours, all four kinds)           — needs the four types, and adapts the campaign
                                                                machinery once (ruling 30)
```

**Why this order.** Slice 0 is the spine: the tables, the service boundary, the panel shell, the shared card
and the File type. Nothing can be built before it, and it is where the ownership/incognito guard has to be
extended, once, for all three new tables — doing it later means three chances to get it wrong.

Slice 1 (Document) and Slice 2 (App) are genuinely parallel: Document is Markdown + a client editor +
block-addressed patches; App is a generation call + a verification pass + one served route. They touch
different server modules, different components, and different tests. They share exactly three append-only
files (table below).

Slice 3 (Canvas) is last of the "heavy" types because it depends on **both** earlier slices' seams: the panel's
type dispatch (Slice 0/1), and the App block — a Canvas that can hold an App needs Slice 2's serving route,
and its poster frames need the export path. It also carries the perf budget, which is only meaningful once the
panel is no longer a preview shell.

Slice 4 (Slides) depends on Slice 0 for the panel and on Slice 3 for the present/export plumbing (PNG export
and the full-screen presentation path share the panel's expand behaviour and the `produce_file` hand-off).
Slides is the one type the spec did not prototype (spec §9.1) — its eval suite is therefore the strongest
gate of the four, not the weakest.

Slice 5 (Alfy's side) is last of the type work because it can only describe types that exist: type-choice
guidance, the offer heuristic, evidence integration, and the project bundle listing.

Slice 6 (first-open tours) lands last, after Slice 5 (**ruling 30** — all four tours are its own, not one per
type slice): it needs the four types to exist and it adapts the campaign machinery once. It does not otherwise
depend on Slice 5's work, and earlier drafts that assigned tours to Slice 5 are superseded.

**Where parallelism is genuinely available:** **Slice 1 ∥ Slice 2**, with one rule — the two append-only files
`src/lib/components/artifacts/artifact-bodies.ts` (the type→body registry) and `src/lib/i18n/artifacts.ts` are
written in slice order: land Document's entries first, then App rebases those two files. Nothing else in the
two slices overlaps.

**Where parallelism is NOT available, and must not be attempted:**

## Phase 3 — adversarial review (per wave, mandatory)

After each wave, one reviewer per disjoint area, on the session's DeepSeek model (never a Claude model), in its
own worktree, never the implementer. Every reviewer hunts, in this order:

1. ownership and incognito gaps across `artifacts`, `artifact_versions`, `artifact_comments`, `artifact_kv`
   (can user A read, edit, comment on, version or export user B's artifact — or see an incognito one outside
   its conversation?)
2. the executed-content surface: the App route's CSP, the iframe sandbox attributes, the `postMessage` origin
   check, and stored-bytes caps
3. silent data loss: a patch that refused nothing it should have refused, or refused everything (hash rule)
4. block-id lifecycle: minted too late, re-minted on load, dropped on reload, duplicated after a paste
5. prompt-prefix stability: any turn-varying tool set or system-prompt text the artifact tools introduce
6. Svelte 5 reactivity bugs (`$state` captured by value, prop mutated locally, `state_referenced_locally`)
7. lazy-load regressions: an editor imported statically into a route or into the panel shell
8. missing EN/HU keys, keys in one locale only, and any user-visible occurrence of the word "Artifact"
9. mobile layout against the mockups at 390×844 (the Document toolbar in particular)
10. dead code, dead exports and any `ALLOWED_WITHOUT_SCOPE` exemption added without a reason

**Rule: for every defect, write a failing test first, then fix it.** Run the full suite after the fixes.

## The model-contract evaluation harness (a gate, not a one-off)

The prototypes proved the App contract only, with canned data everywhere else. **A type's slice is not done
until its suite has been run against the real model and the result is attached to the slice report.**

- **Location:** `scripts/eval-artifact-contracts/`, following the existing pattern in
  `scripts/eval/README-option-a-fidelity.md`: a **pure scoring module** (`*-scoring.ts`) that is unit-tested in
  CI, and a **live orchestration script** (`run.ts`) that talks to the model and is **not** in CI.
- **CI runs:** the scoring module's tests and the fixture-driven dry run only. Nothing that needs a model.
- **Unconfigured is not a failure:** with no endpoint/model configured the script exits `0` with an explanation
  (the pattern `scripts/eval/README-option-a-fidelity.md` establishes). It must never be a hard dependency of
  `npm test` or `npm run build`.
- **Results are gitignored** (`scripts/eval-artifact-contracts/results/`), and the README documents exactly
  what has to be configured for a real run.
- **Suites:** `app` (the P1 suite, rerun as the regression gate, thinking off + verification pass on),
  `document` (patch applies / refuses correctly / stays in scope), `canvas` (diff parses, applies, is one a
  human would accept), `slides` (valid JSON, correct language, no invented facts), `verify` (does the
  verification pass catch the three known bug classes: wrong key, mislabelled aggregate, wrong unit/gloss).
- **Run on the box before a slice is called done:**
  `npx tsx scripts/eval-artifact-contracts/run.ts --suite <type>` with the endpoint configured, results written
  under `scripts/eval-artifact-contracts/results/`, the numbers summarised in the slice report.
- **A weak result changes the design, it is not argued away** (spec §8.1): a refusal rate that is too high, or
  a Canvas diff a human would reject, means the interaction changes (for example, Alfy proposes a diff the user
  approves) rather than the bar moving.

## Owner decisions already made (do not reopen)

Spec §2's sixteen decisions, condensed — the full text is authoritative and lives in the spec:

2. One card, one panel, shared by all five types.
3. A checklist card is tickable in place (first five items, "+N more").

5. Your words win: a patch to a block you changed is refused, visibly, per op.

7. Comments are one shared feature across types (`text` / `node` / `point` anchors); `@Alfy` produces an edit

| 17 | The panel keeps its file path and component name (`document-workspace/DocumentWorkspace.svelte`) | three live callers and a pinned source-scan reference in `src/lib/shared/file-types/no-ad-hoc-maps.test.ts:164` (**ruling 10** corrected an earlier draft that also cited `DocumentsList.test.ts`, which does not pin it). | 19 | `artifact_versions` and `artifact_comments` are registered in `user-scoped-tables.ts` as `erasure: "cascade"` with `resets: ["workspace"]` **only** | `artifacts` itself survives Clear Memory for `generated_output` rows (`account-lifecycle/index.ts:85-100` deletes only non-generated artifacts), so a memory-scope entry here would strip history and comments from an artifact that survives. | 20 | `artifact_kv` is **not** registered (it has no user column) and is reached only through the artifact that owns it | the completeness guard keys on person columns; a key-value row without its artifact is unreachable by design |
| 21 | The type→body registry and the i18n dictionary are append-serialized across slices, rather than "resolved" by a discovery mechanism | a one-line rebase is cheaper and more honest than a clever loader nothing else in this repo uses |
| 22 | The evaluation harness lives at `scripts/eval-artifact-contracts/` and its suites are added per type | the spec requires it as a gate; putting it next to the existing eval pattern keeps the CI/live split identical to what already works |
