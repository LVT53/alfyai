## F5 (done): the first message never passes through an English page
Cause. The landing sends with a full document navigation, so the chat's first frame is server-rendered HTML. The interface language was only applied in the shell layout's `onMount` (`initSettings`), so the server render and the first hydrated frame were English: the bootstrap view ("Starting conversation...", composer "Type a message...") and then the header "New Conversation" (the stored default title) until the generated title came.
- `routes/(app)/+layout.svelte`: sets `uiLanguage` from `data.userUiLanguage` in its script (`untrack`, first value only). `routes/+layout.svelte`: `if (!browser) uiLanguage.set("en")` puts the baseline back at the start of every server render (a render is synchronous, so a write and its reads are in one request; the login page is never drawn in the previous reader's language). `onMount`'s `initSettings` stays (it persists and handles the no-server-pref case).
- `shared/conversation-title.ts` (new, browser-safe): `DEFAULT_CONVERSATION_TITLE` (the stored sentence, one place; used by `services/conversations.ts`, `stores/conversations.ts`, `title-generator.ts`, the chat page's "is it still untitled" check), `isUntitledConversationTitle`, `conversationDisplayTitle`. New key `chat.untitledConversation` (EN "New Conversation", HU "Új beszélgetés"). Shown through it: `ConversationTitleText` (title bar, phone header, sidebar), the chat page `<title>` and the h1 tooltip, the Header tooltip, `HomeRecent`, the pinned reorder label. The stored value is unchanged (the landing's reuse check, `maybeTriggerTitleGeneration` and the store compare against it). `ConversationTitleText` compares the STORED title, so changing the interface language while untitled is not mistaken for a generated title (no typewriter).
- The bootstrap view stays part of the chat: `.starting-conversation` (spinner + label, `role=status`) is invisible for 600 ms and then fades in, so a normal bootstrap of a few dozen ms shows an empty chat area (header, composer) and then the bubble, not a second page.

## F16 (done): a card no longer drops in late and pushes the text down
Cause, measured. A `create_artifact` / `edit_artifact` call reaches the browser only once the model has written the whole item (the call carries the body), so its tool row and card ALWAYS arrive late. They were drawn in the thinking rail above the text, so the sentences the reader was reading moved down by their height: +158.9 px (row + skeleton card) and +148.2 px more when the card took its checklist preview (the skeleton is ~148 px shorter than the finished card, so a placeholder of the skeleton's height would not have held: reserving room needs the final height, which nothing knows at the start, and the browser gets no "call started" signal at all: the server ignores the SDK's `tool-input-start`, and adding one means a new event through model-run, chat-turn, the stream frames, the client merge and persistence).
Fix ("the card goes where it moves nothing"). The turn's artifact calls are what it MADE, not a step of how, so `MessageBubble` now draws their rows and cards after the text (`.message-deliverables`, the same `ToolActivityList` / `ToolActivityRow` / `ArtifactCard`, testids unchanged) and the rail keeps the steps. `isArtifactToolCall` (`utils/tool-calls.ts`: exactly create_/edit_artifact); `thinkingSegmentsForDisplay` no longer carries them; the "preparing" status and the depth chip count deliverables as progress; the rail's segment list stays reference-stable across streamed tokens (`rawThinkingSegments` memo). The order is the same live and after a reload.
Tests: `tests/e2e/artifact-card-arrival.spec.ts` (2) with a scripted late-card turn (`tests/fixtures/ai/late-card-scenario.ts`, a branch in `tests/mocks/ai-provider/openai-compatible-provider.ts`: four intro sentences, 2.5 s of "writing", `create_artifact`, a closing sentence): every frame the sentences' top edge must not move after the card arrives, the card is below the sentences, in a short chat (and after a reload) and in a long one. Red before (158.9 / 307.1), green after. Unit: `MessageBubble.test.ts` +4, `tool-calls.test.ts` +1.
Screenshots `fb7-shots/F16-before-end-state.png` (the old layout: row and card above, the closing text pushed under the composer) and `F16-after-end-state.png` (sentences where they were, then the row and card).
