## The chunk gate (read this)
The brief said the editor's ceiling does not move. It does not, but it took a design change to keep it: the preview needs the editor's own `CanvasBoard`, and **this build uses Rolldown (Vite 8), which puts a module two lazy entries both import into a chunk of its own** (Rollup's "already loaded" shortcut does not exist). Measured on my first attempt (the preview imports the board): the board and `@xyflow` leave the editor's chunk, the editor's exclusive closure goes to **73,283 B**, then 74,261 B with the preview reached only through the editor module, and the gate also fails `@xyflow … which the CanvasEditor chunk does not load` (a CSS-only manifest key). The fix: `CanvasEditor.svelte`'s *module script* (`loadHistoryPreview`) is the only importer of `canvas/history-parts.ts` and hands it `CanvasBoard`, `SvelteFlowProvider`, `ViewportPortal` **and `sameCamera`** (`provideBoardParts`); the preview imports none of them (a `board-model.ts` import alone created a 13th chunk, +751 B). History's registry asks for it through the editor module (`import("../canvas/CanvasEditor.svelte").then(e => e.loadHistoryPreview())`; the Canvas panel is open whenever History is, so the module is loaded already). Result, built here and measured with `p5/vb3-closure.mjs` (exclusive chunks of the editor's closure):

## Deviations and concerns
1. **The editor has 81 B of headroom** (72,623 of 72,704). Any further first-paint addition to the Canvas editor needs another extraction or a recorded raise. The Rolldown rule is in AGENTS.md; a future preview must reach the editor's modules through `provideBoardParts`, not by import.
2. **The chat route is still over its baseline by 8,946 B** — inherited from VB-2 (+82 B mine: the board's and the App's strings and two registry lines); nothing heavy joined it. VB-2's recommendation (re-baseline or the closure rule) stands.
3. The first commit's subject says "WIP:" (the coordinator asked for a WIP commit at a stable point); it is the finished Part 1. I did not rewrite history (no rebasing).
4. The App registers `reload` but **no `flush`** (the brief says to register both "the way the Document does"): an App has nothing the reader typed to save, and a `flush` that waited for a running rebuild would also hold up the chat page, which awaits it before every turn. History opened during a rebuild shows the new moment when it lands (it listens to `subscribeArtifactChanges`).
5. Left alone: `DocumentWorkspace.svelte`'s `artifactTypeAndVersion` snippet prints `v{n}` but sits in a branch that cannot render (`activeDocument.kind` is falsy there) — dead code, with `artifacts.card.version(A11y)` and `artifacts.canvas.chat.version` unused; not in the brief, easy to delete.
6. A board preview's camera is fitted from the stored sizes (`estimatedNodeSize`), not measured: a diagram that grows after Mermaid draws it can sit a little off until the reader presses Fit.
7. "Compared with now" tags a block the old version has and now lacks as *New* (what Restore would add) and what now has and it lacks as *Removed*: coherent as "what Restore does", but the owner may prefer other words there.
8. Hungarian for the board's tags and the App's lines was written for this change (the rebuild copy and `appRuns`/`restoreAppData` are §8's); a native read before release is worth it.
9. The probe is a `HEAD`: it relies on SvelteKit answering `HEAD` with a `GET`-only route (the e2e passes, so it does today).
10. Not covered: an incognito chat's History of a board or App (the scope is the same `conversationId` plumbing as the Document's, `version-bodies` keys by it, the unit test covers the key; no incognito e2e), and the library row's live follow of an edit (unit-tested pieces only; the e2e covers first paint).

## Hand-off
- Registry: `history/history-previews.ts` has all three kinds; a new kind adds one loader (a kind that needs the editor's board reaches it through its editor module, `loadHistoryPreview`).
- `ArtifactBodyProps.onOpenHistory` (panel → body) opens History; `ArtifactPanelBodyActions` is `{openDownload, toggleComments, flush, reload, reviewPending}`.
- `AppFrame`'s `previewVersionId` is the one switch for a read-only frame; do not add a second way to run an old version.
- `history/version-bodies.ts` (`versionBody`) is the one fetch of a stored body for a preview; `history/line-diff.ts` (`diffLines`, `foldUnchanged`) the one line diff of the browser (the server's counts stay in `moments/line-diff.ts`).
- `getArtifactLatestVersions` (knowledge `store/documents.ts`) is where a library row gets its newest version's author/kind.
- `p5/vb3-closure.mjs` lists the editor's exclusive chunks and sizes; `p5/vb3-chatroute.mjs` the chat route's closure and the heavy libraries in it; `p5/vb3-snap.sh` builds a snapshot of the worktree in the scratchpad so the tree can be edited meanwhile (both numbers above came from them).
