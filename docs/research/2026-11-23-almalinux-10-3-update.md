# Updating AlmaLinux 10.2 to 10.3: the update path, the NVIDIA stack and Node.js 26

Primary sources checked on 23 November 2026: the AlmaLinux 10.3 announcement (16 November) and the posts it links, the AlmaLinux 10.3 release notes, the `repo.almalinux.org` and `vault.almalinux.org` indexes with the headers and payloads of the RPMs in them, Red Hat's RHEL 10.3 release notes and Application Streams life cycle, NVIDIA's driver installation guide, data center driver release notes and CUDA installation guide (all updated 2 to 9 November), AlmaLinux's and NVIDIA's RPM repositories, `nodejs/Release`, the `nodejs/node` changelogs, and Docker, Tailscale and Virtualmin vendor pages and packages. Nothing on the server was touched. Written by Sonnet 5.5 in a shortened session (the coordinator asked for the note early): what was not reached is listed under "Not verified". The package versions below are those in the repo trees on 23 November, which already contain post-release builds (newer than the release notes' numbers).

## Bottom line

1. No dedicated minor-upgrade command exists: AlmaLinux's own instruction is `$ dnf upgrade -y` for any AlmaLinux 10 system, with no before or after step (stated, [10.3 release notes, Upgrade Instructions](https://wiki.almalinux.org/release-notes/10.3.html#upgrade-instructions)). A kernel update needs a reboot.
2. On disk the update swaps `almalinux-release`, `-repos` and `-gpg-keys` to `10.3-15.el10`: `/usr/lib/os-release` gets `VERSION_ID="10.3"`, `/etc/almalinux-release` and the CPE follow; repo files keep `$releasever` and the key file `RPM-GPG-KEY-AlmaLinux-10`; the release package has no scriptlets (stated, RPM payloads, section 1). `$releasever` should stay `10` (inferred).
3. No repo, GPG-key or Secure Boot change is announced; shim is the same `shim-x64-16.1-4.el10.alma.1` in both trees, dual-signed (stated, [announcement](https://almalinux.org/blog/2026-11-16-almalinux_103_and_99_stable/), [Secure Boot page](https://wiki.almalinux.org/documentation/secure-boot-2023-certificates.html)). AlmaLinux lists no known issues for 10.3 (stated).
4. Pre-upgrade checks AlmaLinux names (stated): authselect stops merging groups by default (`authselect enable-feature with-group-merging`), fapolicyd 1.4 to 2.0, GCC Toolset 16 defaults to gnu++20, Podman 6 (CNI, BoltDB, slirp4netns, cgroups v1 and iptables handling removed; `containers-common` conflicts with podman < 6), ModSecurity with CRS 4.22 is new.
5. RHEL 10.3's notes add (stated): `sshd_session_t` and `sshd_auth_t` become SELinux-enforcing, OpenSSL drops its startup certificate self-check, netfilter 7.2 no longer supports `nf_conntrack_max = 0`, `grub2-install` now runs after grub2 updates on BIOS machines. None of the other server packages (httpd, Postfix, Dovecot, BIND, Python, PostgreSQL, MariaDB) changes major version.
6. Kernel: the release kernel `6.12.0-264.16.1.el10_3` is affected by NoisyTCP (CVE-2026-99288); the newest tree kernel `6.12.0-264.17.1.el10_3` lists the fix in its RPM changelog (stated). Boot that one, not the older 10.3 kernel (inferred).
7. NVIDIA: AlmaLinux's notes say nothing. NVIDIA's R580, R595, R615 and R620 notes list RHEL 10.x only for x <= 2, and CUDA 13.5's validated AlmaLinux 10 row is 10.2 with kernel 6.12.0-211 (stated). The AlmaLinux repo has an el10_3 kmod only for 620.70.06-4 (built for 264.16.1); there is none for 615.71.10 (stated).
8. Packages in the same `dnf upgrade` that restart their service (stated, scriptlets): tailscale (`systemctl try-restart tailscaled.service`) and docker-ce (`mark-restart-system-units docker.service`).
9. Node: `nodejs` stays 22.23.4 and owns `/usr/bin/node`; `nodejs26` 26.12.1-3.el10_3 is new, installs only `/usr/bin/node-26`, no alternatives (stated). Node 26 "Lithium" is LTS since 2026-10-28, end of life 2029-04-30; Red Hat retires its Node.js 26 stream Apr 2029, Node.js 22 Apr 2027.
10. Gaps (Red Hat's generic update chapters, Tailscale and Virtualmin docs, NVIDIA's DKMS and Secure Boot text): see "Not verified".

## How the sources were read

Pages and RPMs were downloaded with `curl` and read as raw text; RPM headers (provides, scriptlets, changelog, file lists) and payloads were parsed locally, so those facts are the packages' own metadata. A summarising fetch tool was used only for a first pass over the announcement and release notes, and every figure used here was re-read from the raw page. Links in the announcement followed: the release notes, the 10.3 beta post, the PwnEscape, php2shell, ZDI-CAN-33367, CVE-2026-98432 and CVE-2026-98276 posts, and the next post (NoisyTCP). Not followed: ISO, cloud-image, CRB, Btrfs, i686 and EPEL-v2 pages (no bearing on an in-place update). Docs.redhat.com pages were read as `https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/10/<slug>` (the `html/10.3_release_notes` URL redirects there).

## 1. Is a minor release a normal `dnf upgrade`, and what changes on the system?

- The release notes give one command for updating AlmaLinux OS 10 to 10.3: `$ dnf upgrade -y` (stated, [release notes](https://wiki.almalinux.org/release-notes/10.3.html#upgrade-instructions)). Beta testers only: `$ dnf install https://repo.almalinux.org/almalinux/almalinux-{release,repos,gpg-keys}-latest-10.$(uname -m).rpm` then `$ dnf upgrade -y` (stated, same page; not for a stable 10.2 box). The announcement has no procedure and asks readers to try a test machine first (stated, [announcement](https://almalinux.org/blog/2026-11-16-almalinux_103_and_99_stable/)).
- `almalinux-release-10.3-15.el10` payload, read from the RPM ([package](https://repo.almalinux.org/almalinux/10.3/BaseOS/x86_64/os/Packages/almalinux-release-10.3-15.el10.x86_64.rpm)) (stated): `/usr/lib/os-release` has `VERSION_ID="10.3"`, `PRETTY_NAME="AlmaLinux 10.3 (Mauve Lion)"`, `CPE_NAME="cpe:/o:almalinux:almalinux:10.3"`, `SUPPORT_END=2035-06-01`; `/etc/almalinux-release` reads `AlmaLinux release 10.3 (Mauve Lion)`; `/etc/system-release-cpe` is `cpe:/o:almalinux:almalinux:10.3`. It also ships `/etc/dnf/protected.d/almalinux-release.conf`, systemd presets and `/usr/lib/sysctl.d/50-redhat.conf` (`kernel.kptr_restrict = 1`, `rp_filter`). Its header carries no install scriptlets. It was not diffed against the 10.2 package (see Not verified).
- `$releasever`: the package provides `system-release(releasever) = 10`, `system-release(releasever_major) = 10` and `system-release(releasever_minor) = 3` (stated, same RPM header). The repo files use `$releasever` in the mirrorlist (`https://mirrors.almalinux.org/mirrorlist/$releasever/baseos`) and a commented baseurl (`https://repo.almalinux.org/almalinux/$releasever/BaseOS/$basearch/os/`) (stated, [almalinux-repos-10.3-15.el10](https://repo.almalinux.org/almalinux/10.3/BaseOS/x86_64/os/Packages/almalinux-repos-10.3-15.el10.x86_64.rpm)). So `$releasever` stays `10` and the repos follow the newest minor (inferred; dnf's own derivation rule was not re-read). The `10/` tree has the same timestamp as `10.3/` on [the repo index](https://repo.almalinux.org/almalinux/) (stated); that `10/` is the 10.3 tree is inferred.
- Debug and source repos point at `https://vault.almalinux.org/$releasever/...` (stated, same repo RPM). Vault policy: the FAQ says a minor version reaches end of life when the next one is released ([FAQ](https://wiki.almalinux.org/FAQ.html), stated; the FAQ's table only lists 8.x and 9.x, page dated 2025-12-01). On 23 November `repo.almalinux.org/almalinux/10.2/` (dated 05-Oct-2026) and `vault.almalinux.org/10.2/` both still exist ([vault index](https://vault.almalinux.org/), stated). No vault policy page exists at `wiki.almalinux.org/vault.html` (HTTP 404).
- GPG: `almalinux-gpg-keys-10.3-15.el10` ships one file, `/etc/pki/rpm-gpg/RPM-GPG-KEY-AlmaLinux-10` (stated, package payload); the key file on the repo root is dated 25-May-2025 ([index](https://repo.almalinux.org/almalinux/), stated). Neither the announcement nor the notes mention a key change (stated). Content was not compared with the installed key.
- Secure Boot: `shim-x64-16.1-4.el10.alma.1` is the newest in both trees ([10.2](https://repo.almalinux.org/almalinux/10.2/BaseOS/x86_64/os/Packages/), [10.3](https://repo.almalinux.org/almalinux/10.3/BaseOS/x86_64/os/Packages/), stated) and is dual-signed with the Microsoft 2011 and 2023 CAs, and the page says no action is needed now ([page](https://wiki.almalinux.org/documentation/secure-boot-2023-certificates.html), stated). The same transaction updates `grub2-efi-x64` `2.12-46.el10_2.alma.1` to `2.12-56.el10.alma.1` and `mokutil` `0.7.2-4.el10.alma.1` to `0.7.2-7.el10_3.alma.1` (stated, listings).

## 2. Before and after the in-place update

AlmaLinux, announcement ([link](https://almalinux.org/blog/2026-11-16-almalinux_103_and_99_stable/)) and release notes ([link](https://wiki.almalinux.org/release-notes/10.3.html)):

- Known issues: none listed; problems go to bugs.almalinux.org (stated). Removed or deprecated packages: the "Removed packages" table lists only RHEL-specific items (`insights-client`, `rhc*`, `redhat-*`, `kmod-redhat-*`, `openssl-fips-provider`, `virtio-win`, subscription-manager GUI parts and similar); no distribution package a server uses is removed (stated).
- Check before upgrading (stated, announcement): `authselect` no longer merges groups; re-enable with `authselect enable-feature with-group-merging` if local files and SSSD are combined. `fapolicyd` 1.4 to 2.0 changes parallel decisions and transactional policy; test rules and trust DB on a non-production host. GCC Toolset 16 defaults to gnu++20; use `-std=gnu++17` to keep the old standard (system compiler unchanged).
- ModSecurity 2.9.14 with CRS 4.22 returns to EL10; CRS 4 reorganised the rules, review any tuning before production traffic (stated). It is a new package, so an upgrade does not install it (inferred).
- Podman 6 (stated, announcement and release notes): CNI gone, BoltDB gone, pasta replaces slirp4netns, cgroups v1 unsupported, firewall rules via nftables not iptables. Vendor defaults move to `/usr/share/containers`; anything in `/etc/containers` is kept by a `%posttrans` scriptlet and still wins; rootless defaults go in `/etc/containers/containers.rootless.conf.d/`. `containers-common` conflicts with `podman < 6`, `buildah < 1.44` and `skopeo < 1.23`; netavark and aardvark-dns carry an epoch bump.
- The 10.3 kernel includes 30 CVE fixes that RHEL 10.2's last kernel (`6.12.0-211.74.1.el10_2`) had and RHEL 10.3 lacks, so the update does not reintroduce them; plus 6 community-requested fixes (stated, [release notes](https://wiki.almalinux.org/release-notes/10.3.html#kernel-security-fixes-not-available-in-rhel-10-3)).
- NoisyTCP, a remote kernel crash via TCP, was posted the same day as the release: the post lists `kernel-6.12.0-264.16.2.el10_3` as the patched build in testing, and says the AlmaLinux 10 kernels are affected ([post](https://almalinux.org/blog/2026-11-16-noisytcp-cve-2026-99288/), stated). The 10.3 tree now has `kernel-6.12.0-264.17.1.el10_3`, and its RPM changelog has the line `inet: reject unhashed sockets during established lookups {CVE-2026-99288}` ([RPM](https://repo.almalinux.org/almalinux/10.3/BaseOS/x86_64/os/Packages/kernel-6.12.0-264.17.1.el10_3.x86_64.rpm), stated). The tree also holds `264.9.1`, `264.15.1` and `264.16.1` (stated). A box that holds `264.16.1` and `264.17.1` should boot the latter (inferred).
- AlmaLinux's own kernel-update recipe: `sudo dnf clean metadata && sudo dnf upgrade`, then `sudo reboot`, then confirm with `uname -r`; the post adds that mirrors sync every few hours ([PwnEscape post](https://almalinux.org/blog/2026-10-16-pwnescape-cve-2026-99999/), stated).
- AlmaLinux's PHP backports only update PHP installed from AlmaLinux's repos; PHP from a hosting control panel needs that vendor's fix ([php2shell post](https://almalinux.org/blog/2026-10-21-php2shell-cve-2026-109618-cve-2026-109619/), stated). Whether Virtualmin ships its own PHP here is not checked.

Red Hat, RHEL 10.3 release notes (pages under `https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/10/`, slugs given):

- `whats_new-rhel_10_3_new_features_and_enhancements_security` (stated): seven SELinux domains move from permissive to enforcing: `powerprofiles_t`, `qgs_t`, `redfish_finder_t`, `sshd_auth_t`, `sshd_session_t`, `systemd_mountfsd_t`, `systemd_oomd_t`. OpenSSL no longer checks a service's own certificate chain at startup. New opt-in `NO-HMAC-SHA1` crypto-policies subpolicy; `rpm-sequoia` now follows the active policy instead of a hard-coded PQC override. No change of the default crypto policy is stated.
- `..._new_features_and_enhancements_networking` (stated): netfilter 7.2 removes DCCP and UDP-Lite conntrack support, no longer supports `net.netfilter.nf_conntrack_max = 0`, and disables payload mangling in user namespaces for `nfqueue` writes and `nftables` payload rewrites. `firewalld` is rebased to 2.4.2 (the AlmaLinux trees carry `2.4.3-4.el10_2` in both 10.2 and 10.3, so no firewalld change comes with this update: inferred from identical NVRs).
- `..._software_management` (stated): `dnf-automatic` now takes a systemd inhibitor lock so scheduled reboots cannot interrupt an active transaction; `dnf repolist -v` shows `Repo-unique-NEVRAs`; the rpm `syslog` plugin logs are viewable with `journalctl -t rpm`.
- `..._boot_loader` (stated): `grub2-install` now runs automatically after `grub2` updates on AMD64/Intel 64 machines with BIOS firmware; the note warns it can hit a wrong BIOS boot partition and says to check the output of the update. UEFI is not mentioned (whether the server is BIOS or UEFI is not known to me).
- `..._deprecated_features_compilers_and_development_tools`: `pcp-pmda-bcc` no longer ships in new PCP builds; an installed copy stays at the 10.2 version (stated). `..._deprecated_packages`: `iptables-nft`, `iptables-libs`, `ipset`, `vsftpd`, `wget`, `ftp` and others stay deprecated, support unchanged (stated).
- `..._known_issues_*` (kernel, file systems, compilers, virtualization, installer and older-release pages): nothing touches httpd, Postfix, Dovecot, BIND, Python, databases, Docker or NVIDIA; the items are xxhash64 in FIPS mode, Marvell QLogic and Emulex `lpfc` HBAs, Windows-guest and Nutanix VM cases, the `grafana-pcp` vLLM dashboard (stated).
- `..._upgrade_and_conversion` is the RHEL 9 to 10 leapp path (9.9 to 10.3), not minor updates (stated).
- After the update (stated, [NVIDIA post-installation page](https://docs.nvidia.com/datacenter/tesla/driver-installation-guide/latest/post-installation-actions.html)): `dnf needs-restarting -r` exits 1 when a reboot is needed (kernel, systemd, and the NVIDIA driver packages register themselves); `cat /proc/driver/nvidia/version` shows the loaded driver version.

## 4. NVIDIA

AlmaLinux release notes and announcement: nothing about NVIDIA, kmod packages or kernel-module signing; the only kmod line is the removed `kmod-redhat-*` (Red Hat Driver Update Program modules) ([release notes](https://wiki.almalinux.org/release-notes/10.3.html#removed-packages), stated).

**AlmaLinux's own driver repo** ([wiki page](https://wiki.almalinux.org/documentation/nvidia.html), last updated 2026-03-11):

- AlmaLinux builds and ships NVIDIA open-driver packages for AlmaLinux 10, 9 and Kitten 10 on x86_64 and aarch64: Secure Boot-signed and built as kmods, so no DKMS build runs at install or update (stated).
- Install: `sudo dnf install almalinux-release-nvidia-driver`, then `sudo dnf install nvidia-open-kmod nvidia-driver` (stated). Its common-problem note: `modprobe: ERROR: could not insert 'nvidia_drm': No such device` usually means the running kernel differs from the latest installed kernel; a reboot fixes it (stated).
- `almalinux-release-nvidia-driver-10-5.el10_1` (identical in the 10.2 and 10.3 `extras` trees) installs `/etc/yum.repos.d/almalinux-nvidia.repo` with `baseurl=https://nvidia.repo.almalinux.org/cuda/$releasever/$basearch/`, `metadata_expire=6h`; its `%post` runs `/usr/bin/crb enable` and it requires `epel-release` (stated, [package](https://repo.almalinux.org/almalinux/10.3/extras/x86_64/os/Packages/almalinux-release-nvidia-driver-10-5.el10_1.x86_64.rpm)).
- Repo listing ([Packages](https://nvidia.repo.almalinux.org/cuda/10/x86_64/Packages/), 23 November, stated): `kmod-nvidia-open` builds (590.48.01 onward) are `590.48.01-1.el10_1`, `595.45.04-1.el10_1`, `595.58.03-1.el10_1`, `595.71.05-1.el10_1` and `-2.el10_2`, `610.43.02-1/2/3/6.el10_2`, `610.57.04-1.el10_2`, `615.71.09-1.el10_2`, `615.71.10-1.el10_2`, `620.70.06-2.el10_2`, `-3.el10_2` and `-4.el10_3`. The dist tag names the minor the build is for; only `620.70.06-4.el10_3` is an el10_3 build. Branch 580.x kmod builds were not listed.
- `kmod-nvidia-open-620.70.06-4.el10_3` says it is built for kernel 6.12.0-264.16.1.el10_3.x86_64; its `%post` runs `depmod` for that kernel and `weak-modules --add-modules`; it requires per-symbol `kernel(...)` CRC dependencies (the format NVIDIA describes below) (stated, RPM header). ## 6. Docker CE, Tailscale, Virtualmin

- Docker: Docker Engine's install page for AlmaLinux requires a maintained version of AlmaLinux 8, 9 or 10 ([page](https://docs.docker.com/engine/install/almalinux/), stated); the RHEL page lists RHEL 9 and 10 ([page](https://docs.docker.com/engine/install/rhel/), stated). `docker-ce-29.10.0-1.el10` from `download.docker.com/linux/rhel/10/x86_64/stable/` runs on upgrade `/usr/lib/systemd/systemd-update-helper mark-restart-system-units docker.service` in `%postun` (stated, [RPM](https://download.docker.com/linux/rhel/10/x86_64/stable/Packages/docker-ce-29.10.0-1.el10.x86_64.rpm)), i.e. a docker-ce upgrade marks `docker.service` for restart at the end of the transaction (inferred from the helper's name). Docker says live restore reduces container downtime during daemon crashes, planned outages and upgrades, and is enabled by `"live-restore": true` in the daemon config ([page](https://docs.docker.com/engine/daemon/live-restore/), stated). With `iptables` enabled and firewalld running, Docker creates a firewalld zone `docker` (target `ACCEPT`) and a policy `docker-forwarding` ([page](https://docs.docker.com/engine/network/packet-filtering-firewalls/), stated); Docker's nftables backend is documented as experimental ([same page](https://docs.docker.com/engine/network/packet-filtering-firewalls/), stated). - Tailscale: the RPM `tailscale_1.98.10_x86_64.rpm` from `pkgs.tailscale.com/stable/rhel/10/` ([repo file](https://pkgs.tailscale.com/stable/rhel/10/tailscale.repo), [RPM](https://pkgs.tailscale.com/stable/rhel/10/x86_64/tailscale_1.98.10_x86_64.rpm)) has `%postun` with `systemctl try-restart tailscaled.service` when `$1 -ge 1` (package upgrade), and `%preun` stops it only on removal (stated). - Virtualmin: the OS Support page lists AlmaLinux and Rocky Linux 8, 9 and 10 on x86_64 and aarch64 as Grade A (an automated install script plus a maintained update repository) ([page](https://www.virtualmin.com/docs/os-support/), stated).
