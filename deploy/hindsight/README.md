# Private native Memory service

This is the full replacement's service definition, not deployment authorization. It runs upstream Hindsight at commit `9fb28dbd724dc1ce4da7cb4c49008e601db76c5f` with native extraction, ONNX embeddings and Flashrank multilingual reranking. No real account is enrolled by starting it. The app's per-user authority gates migration separately.

## Configuration

1. Generate a fresh paired secret bundle with `python3 provision.py --output .`. It refuses existing files and writes three mode-0600 files, including a persistent native worker ID in `native-db.env`. Use `--worker-id alfyai-memory-staging` if you want to name the worker explicitly. Use a different stable ID for each independent deployment. Keep the bundle in the deployment's secret store and preserve it across container recreation and key rotation.
2. Load `alfyai-tenants.env` into the app's environment. Copy `native-model.env.example` to `native-model.env` and fill the local provider and private app activity endpoint. Pass `native-db.env` to Compose with `--env-file`. It supplies the literal `HINDSIGHT_DB_PASSWORD` to PostgreSQL and the separately percent-encoded `HINDSIGHT_DB_PASSWORD_URI` to Hindsight. For an existing database, preserve its raw password and generate the URI value from that same password. The native master keys and app master keys must match; native model and proxy model must match.
3. Set app `HINDSIGHT_URL=http://127.0.0.1:8888` and leave `HINDSIGHT_WORKER_ENABLED=false` until synthetic verification and rollout approval. The app and native service must reach each other over a private network. Compose publishes only loopback. Keep the native APIs and database on private interfaces. The app pins the deployment's `HINDSIGHT_URL` and any additional base URLs listed in the environment-only `HINDSIGHT_ALLOWED_URLS`. Keep bound endpoints approved until their cleanup finishes. App, model, and activity addresses accept private or loopback IP literals and the HTTP aliases `localhost` and `host.docker.internal`. The transport checks every alias resolution, uses the checked private address, and refuses redirects. Separate direct HTTP(S) agents bypass Node's ambient proxy settings for app traffic; the native proxy also bypasses ambient proxies. Link-local and public addresses are excluded.
4. Configure Memory editing against the shared admission gateway. Load the generated `HINDSIGHT_API_HTTP_INFERENCE_KEY` into both the app and native service environment and set the app’s `HINDSIGHT_CURATION_GATEWAY_MODEL` to the exact gateway model name. This server-only binding derives its endpoint from the approved Hindsight URL and does not add a chat model. An existing local provider selected through `HINDSIGHT_CURATION_MODEL` takes precedence and must still point to `HINDSIGHT_URL/ext/alfyai/inference/v1`.
5. After deployment authorization: `docker compose --env-file native-db.env build` and `docker compose --env-file native-db.env up -d`. Record the resulting image digest. Engine source is pinned and build-verified; base images and transitive Python dependencies are not yet digest/lock pinned, so rebuilding later is not byte-reproducible. Preserve the tested built image for rollback.

Startup LLM verification is disabled because the engine calls its own extension proxy, which starts after engine initialization. A successful `/health` is **not** model readiness. Before enrollment, run synthetic retention, consolidation, publication and recall through the app against this service and verify `/ext/alfyai/capabilities` with an app-derived synthetic tenant credential. This authenticates the observed source commit, extension identity and tenant schema binding. Never substitute a configured commit string for an observed attestation.

Native database LLM request traces and OpenTelemetry traces are disabled in the image and Compose configuration. The native logger defaults to warning because the upstream info logs include recall queries. Operational counters are available through the authenticated inference status endpoint. If restoring a database created with tracing enabled, check and remove historical `llm_requests` under the applicable retention and erasure policy before admitting app traffic. Turning off recording affects new requests.

The native review-only extraction endpoint is off by default in Compose. Set `HINDSIGHT_API_ENABLE_DRY_RUN_EXTRACT=true` in the private Compose interpolation environment and `HINDSIGHT_QUARANTINE_ENABLED=true` in the app only for an authorized deployment. The app submits a single eligible source through its bound tenant and verified bank configuration. It supplies no neighboring conversation and accepts only text with attribution to a chunk of that source. The native call uses the shared inference gateway and may increment inference counters. It creates no facts, documents, or embeddings. Tenant authentication may initialize that tenant's schema before any preview.

For an existing installation adding the worker setting, preserve the configured worker ID in `native-db.env`. Remove any shell-level `HINDSIGHT_API_WORKER_ID` override before running Compose so it uses the deployment value. If a previous installation used the container hostname, verify that it has drained its native processing jobs before changing the ID, or reconcile those jobs using the supported native recovery workflow. Hindsight recovers interrupted work using the recorded worker ID.

## Existing GPU embedding and reranking services

`compose.gpu.yaml` is an optional override for the AlfyAI host's existing authenticated TEI services on host loopback. It selects Hindsight's OpenAI-compatible embedding adapter for the GPU Qwen3-Embedding-0.6B embedder at 1,024 dimensions (its native size) and its TEI adapter for the GPU BGE reranker. The private transport adds the upstream bearer required by the reranker and bridges the native container to host loopback. Native extraction and curation still use the separately configured local LLM through the admission gateway.

Qualify the provider change with fresh isolated PostgreSQL data before using this override. The baseline ONNX embedder stores 384-dimensional vectors. Restoring its populated database directly into this GPU profile cannot convert them. Preserve the baseline pair. A populated database moves to another embedding model with the engine's re-embed, described under "Changing the embedding model" below. PostgreSQL HNSW indexes stop at 2,000 dimensions, so the profile pins 1,024-dimensional vectors (`HINDSIGHT_API_EMBEDDINGS_OPENAI_DIMENSIONS`) and the transport refuses any other size. The 0.6B answers 1,024 natively; the 4B, which answers 2,560, ran here cut to 1,024.

Use a second mode-0600 Compose interpolation file with the validated native image tag (`ALFYAI_TEI_NATIVE_IMAGE`), a dedicated bridge subnet and gateway (`ALFYAI_TEI_BRIDGE_SUBNET`, `ALFYAI_TEI_BRIDGE_GATEWAY`), fixed stage-specific native and PostgreSQL bridge addresses (`ALFYAI_TEI_NATIVE_HOST`, `ALFYAI_TEI_POSTGRES_HOST`), and a fresh `ALFYAI_TEI_EMBEDDING_TOKEN`. Use `ALFYAI_TEI_EMBEDDING_QUERY_PREFIX` only with a retrieval-qualified value. Set `ALFYAI_TEI_EMBEDDING_UPSTREAM_KEY` and `ALFYAI_TEI_RERANKER_UPSTREAM_KEY` in the separate mode-0600 `tei-upstreams.env`, used only by the transport container. Append `-f compose.gpu.yaml` after the base file and deployment-specific overrides. Include both interpolation files using `--env-file`.

Start the dedicated PostgreSQL container first so Compose creates the dedicated bridge before the transport binds. Then start `tei_transport` and `hindsight` from the validated local image. The transport uses host networking to reach the existing loopback services and binds only the dedicated bridge gateway on 17998. Deploy no public or proxy route for it. It accepts inference only from the fixed native container address, verified separately from Docker's declarative configuration. An embed request also needs the private transport bearer. The transport applies a separate single-request limit per GPU endpoint. Its native-only `/status` returns completed route counts.

### Changing the embedding model

Use the engine's own `hindsight-admin reembed` to move a populated database to another embedding model in place (`hindsight_api/admin/reembed.py` in the pinned commit). Production went from Qwen3-Embedding-4B to Qwen3-Embedding-0.6B this way on 2026-11-22. In each schema the command adds an `embedding_next` column of the new model's dimension to `memory_units` and `mental_models`, fills it from the same text the write paths embed, builds the vector indexes on it and swaps it in for `embedding` under a short write lock. It takes the new model from the same `HINDSIGHT_API_EMBEDDINGS_*` environment as the server, `--all-schemas` covers the base schema and every tenant schema, and running it again resumes an interrupted run. Both Qwen3 sizes are 1,024-dimensional here (the 4B was cut to 1,024), so the column type and the index definitions stay the same: the vectors change, the schema does not. `$DC` below is the deployment's usual Compose command line: its project name, `-f compose.yaml`, any deployment override, `-f compose.gpu.yaml` and both `--env-file` interpolation files.

1. Back up as described under "Backup, restore and upgrades", with Memory delivery paused and no native operation outstanding, then stop the server with `$DC stop hindsight`. The engine would let a server keep running on the old model during the fill, but a one-off container from this profile must take the server's fixed bridge address, the only peer the transport serves, and a running server holds it.
2. Serve the new model on host loopback port 7999, where the transport forwards, and confirm which model answers: TEI's `/info` names it. A vector of 1,024 values proves nothing, because the 4B cut to 1,024 has the same length, and the transport checks only the model name in a request, not what answers behind it.
3. Put the same new model name in `compose.gpu.yaml` (`HINDSIGHT_API_EMBEDDINGS_OPENAI_MODEL`), in the transport (`EMBED_MODEL` in `alfyai_tei_transport.py`) and in `EMBED` in `test_tei_transport.py`, which fails if the three differ (`python -m unittest test_tei_transport` in this folder, with `fastapi` and `httpx` installed). The transport answers HTTP 400 to any other name. Recreate the transport so it reads the new name with `$DC up -d --no-deps --no-build --pull never --force-recreate tei_transport`, and wait until it is healthy; `--no-build --pull never` keep Compose from rebuilding or pulling the validated image.
4. Fill and swap with the new model's environment: `$DC run --rm --no-deps --entrypoint hindsight-admin hindsight reembed --all-schemas`. PostgreSQL and the transport must already be up; `--no-deps` leaves them alone. The command prints the new model first, as `provider:model:dimension` (here `openai:/qwen3-embedding-0.6b:1024`), and records it in the new column's comment. From the swap on, a write guard (the `hindsight_reembed` trigger) makes PostgreSQL refuse vector writes from any connection not tagged with the new model, which every server tags with the model it runs: workers defer those writes and HTTP answers 503. Both models have 1,024 dimensions, so the column type cannot tell their vectors apart; the guard keeps a server on the old model from storing vectors in the wrong space.
5. Start the server on the new model, which recreates it, with `$DC up -d --no-deps --no-build --pull never hindsight`, and wait until it is healthy.
6. Once every server runs the new model, remove the guard with `docker exec <project>-hindsight-1 hindsight-admin reembed --finish --all-schemas` (`<project>` is the Compose project name). Use `exec` here: a one-off container cannot take the server's fixed address while the server is up. `--finish` makes no embedding calls and refuses a schema whose swap has not run.
7. Verify before reopening Memory. In every schema `memory_units` and `mental_models` keep their row counts and every row that had a vector still has one, the vectors are 1,024-dimensional and the column comment names the new model, every vector index is valid (`pg_index.indisvalid`), and no `embedding_next` column or `hindsight_reembed` trigger or function is left. Then run a synthetic recall through the app: `/health` is not model readiness (see Configuration).

The command re-embeds `memory_units` and `mental_models` only. The engine's knowledge-bank tables (`kb_*`) also hold embeddings, but that feature is off here (`HINDSIGHT_API_ENABLE_KB` defaults to false and nothing in this folder sets it) and the tables were empty when the move was made; if it is ever enabled, they need a re-embed of their own. The command builds the new column at the new model's dimension, but only the move between two 1,024-dimensional models has been run here: converting a 384-dimensional ONNX baseline database that way is untested, so try it on a copy first. On the AlfyAI host the same TEI embedder also serves the app's own semantic search (`TEI_EMBEDDER_*`, see [docs/configuration.md](../../docs/configuration.md)), so a model change there has an app-side half, the admin model name and re-embedding the app's stored vectors, that this procedure does not cover.

To go back, repeat the steps with the old model's name and TEI service. Restoring the pre-move dump instead also brings back anything erased since, so it falls under "Restore hold". On 2026-11-22 the fill took seconds for a few thousand vectors in all, and production Memory was down about two minutes.

## Tenant security and provisioning

The default `AlfyTenant` is an app-owned implementation of the supported native TenantExtension. App-generated opaque UUIDs route to strict `alfyai_t_<uuid with underscores>` PostgreSQL schemas. The app derives server-only signed credentials from a versioned 256-bit master key; the extension verifies them in constant time and invokes the native migration hook once per tenant per process. New opaque accounts need no manually maintained credential map. Users cannot choose schemas. Workers discover only canonical app schema names. The extension reads the native pool when initialized and opens a short discovery connection during startup; no engine fork is involved.

Master keys can impersonate every tenant: keep them server-side, out of logs/admin responses/backups shared with users. Tenant schemas isolate application requests, not the database administrator. The database and model operator remain trusted. This is self-hosted; configure no external LLM provider if data must stay local.

Rotation: add a new version to both keyrings, retain the old version, then change the app's active version for **new** bank bindings. Existing banks resolve their recorded credential hash against retained versions. Do not remove old versions while any live bank or pending erasure refers to them. Rebinding existing banks requires a separately verified controlled operation; changing the active version does not silently redirect cleanup. Emergency revocation intentionally makes old bindings unavailable until repaired. Static-key compatibility exists through `provision.py --static-tenant <uuid>` and the bundled upstream static extension; it is not a second active provisioning path or the default.

## Background admission

One native process and one replica are required: the admission queue lives in that process's memory and must see every call. Hindsight's own model calls and the app's memory calls (Memory editing, the meaning check and the curation runner) all reach the model through the extension's `POST /ext/alfyai/inference/v1/chat/completions`, which also counts the app's calls. Requests are bounded to 4 MiB, one configured model, non-streaming, and a fixed upstream URL; prompts are not logged by this extension.

A call within the budget goes to the model at once. A call over it waits in a bounded queue (`alfyai_admission_queue.py`) instead of being refused, and goes on when a slot frees. Every live call goes before any background call. Within a priority, Hindsight's own calls and the app's take turns, and within the app's, each account's calls take turns with the other accounts'. Each account's calls keep their order, and so do Hindsight's own, which share one turn. Live calls can hold background work back only while they keep coming, and a person starts each of them. The budget is decided when a call goes on, not when it arrives: while calls wait, the gateway reads the app's activity endpoint again at most once a second, so a call that waited goes on under the reading of that moment. The queue is held in memory only. A restart loses the calls waiting in it, and their callers' own retries take over; no durable queue, scheduler or memory semantics live in this proxy.

The app declares each of its calls with three headers. A call without the priority header is Hindsight's own: background, in Hindsight's turn, waiting up to the native wait below.

- `X-AlfyAI-Admission-Priority`: `interactive` for a call a person is waiting for, `background` for the rest. Any other value is background.
- `X-AlfyAI-Admission-Lane`: the account's turn, 1 to 64 lowercase hexadecimal characters. The app sends a digest of the account, never its id. Anything else shares one app lane.
- `X-AlfyAI-Admission-Wait-Ms`: how long the call may wait, in whole milliseconds. Missing or malformed means the longest wait.

Three extension settings bound the queue. They are read when the service starts, and a value out of range stops it from starting.

- `HINDSIGHT_API_HTTP_ADMISSION_MAX_WAITING` (32, from 0 to 1024): how many calls may wait. Each holds its request, up to 4 MiB, in memory. One more is refused at once with 429 "Memory inference queue full". At 0 nothing waits, and a call over the budget is refused at once, as before the queue.
- `HINDSIGHT_API_HTTP_ADMISSION_MAX_WAIT_S` (900, from 1 to 86400 seconds): the longest any call waits, whatever it declares.
- `HINDSIGHT_API_HTTP_ADMISSION_NATIVE_WAIT_S` (600, from 1 to 86400 seconds): how long Hindsight's own calls wait.

A call that has waited as long as it may is refused with 429 "Memory inference wait exceeded". Both refusals carry `Retry-After: 5`, and the caller's own bounded retries decide what follows. A caller that gives up first (Hindsight's own request timeout, the app's abort) leaves the queue within a second, and is asked once more as it is admitted, so it is never sent to the model afterwards.

The authenticated `GET /ext/alfyai/inference/status` reports counters since the process started: `active` and `peak` (calls at the model now, and the most at once), `completed` and `duration_ms` (calls that ran, and their total time at the model), `waiting` (calls in the queue now), `waited`, `wait_ms` and `max_wait_ms` (calls that queued and have left the queue, sent on or not, with their total and longest wait), `refused_full` and `refused_wait` (each kind of refusal), `rejected` (both together), and `abandoned` (callers that left before their call went on, while they waited or as they were admitted: a caller whose own timeout is shorter than the wait it was given).

Hindsight gives up on its own model call after `HINDSIGHT_API_LLM_TIMEOUT` seconds (120 by default at the pin), and the queue may hold that call up to the native wait before the model's own run, which the gateway cuts off at 180 seconds. The template therefore sets the timeout to 800, above the default native wait of 600 plus 180; otherwise the engine's retries would do the waiting again, each one wasting a generation the gateway already started. `test_effective_config.py` checks, in the image, that every LLM timeout the engine parses from `compose.yaml` outlasts the native wait plus 180 seconds. Lower `HINDSIGHT_API_HTTP_ADMISSION_NATIVE_WAIT_S` with the timeout if a deployment lowers it.

Default admission is one. Six is an explicit operator ceiling only when `HINDSIGHT_OVERNIGHT_IDLE=true` and the authenticated app activity endpoint returns a fresh (two-second), healthy, inactive signal. Foreground send/stream lifetimes write content-free leases to shared SQLite; crashes retain a conservative expiry. Missing/failed/stale activity signals fall back to one. Starting foreground work stops additional admissions above one, calls already waiting included; already admitted requests finish, so instantaneous total may remain six. Activity writes use a five-millisecond SQLite contention timeout. Status polls only read unexpired leases. Tracking failures never stop chat. They warn without content and mark that app process unhealthy for the conservative request budget. A partial per-process tracking failure not visible to the endpoint process cannot guarantee immediate downshift; six remains the hard gateway ceiling. This is load control, not a security authorization boundary. Never claim universal model concurrency: foreground chat and other app auxiliary calls are outside the background proxy.

### Fan-out and retries

The native global semaphore (`HINDSIGHT_API_LLM_MAX_CONCURRENT`) caps Hindsight's own fan-out, and the template keeps it at one. Before the queue, the admission refused an over-budget call at once, and the engine retries a refused call only three times within seconds (1, 2 and 4 second backoff). With native fan-out higher than the budget, calls behind a long extraction ran out of retries and the whole retain failed, and an app call sharing the slot left a fact consolidation-failed (production, 2026-11-21 and 2026-11-22). The template therefore raises `HINDSIGHT_API_LLM_MAX_RETRIES` to twelve, so a refused call waits several minutes for the slot. With the queue, a call over the budget waits instead of spending retries, so both settings may move back toward the engine's defaults, but only as measured below. A fact already marked failed is reset with the engine's `POST …/banks/{bank_id}/consolidation/recover`, followed by a consolidation run.

### When fan-out and retries may change

Measure on the non-production Hindsight (built from this folder with its own secret bundle and worker ID), never on production. Hold the model busy overnight with background work and read `/ext/alfyai/inference/status` through the night. Raise `HINDSIGHT_API_LLM_MAX_CONCURRENT` one step at a time, a night per step, and only while `refused_full`, `refused_wait` and `abandoned` stay 0 and the mean wait of a queued call (`wait_ms / waited`; nearly all of them are background calls) stays under half of `HINDSIGHT_API_HTTP_ADMISSION_NATIVE_WAIT_S`. Bring `HINDSIGHT_API_LLM_MAX_RETRIES` back toward the engine's default of 3 only after a week with no refusals. Each change is an operator step the owner approves; record the readings with it.

## Pending bank configuration

The app durably records the approved binding before its single native configuration PATCH. If that request's outcome is unknown, readback of the exact expected configuration settles it. A missing bank or an existing bank with incomplete configuration leaves cleanup pending, because an accepted write can commit after the read. The app never resends an unconfirmed configuration mutation. Older bound banks without a configuration receipt may have multiple unresolved writes and remain held for operator reconciliation.

Automatic pending retries are bounded by the existing job engine. An absent or partial configuration can remain unresolved if the request never reached Hindsight or failed partway. Verify quiescence of the original bound service and reconcile there before recording completion. A status poll showing 404 is insufficient. In this window the app's second fence prevents user text from entering the unconfirmed bank.

## Bank config 2 (Memory part 2)

Bank config 2 (`nativeBankConfig` in `src/lib/server/services/memory-profile/contracts.ts`) adds part 2's mission sentences and two `entity_labels` groups, `kind` and `subject`, so extraction labels every new fact. A bank the previous release configured (stored version `9fb28dbd…`, config 1) is upgraded by its next delivery or Memory edit: the app checks that the live config is one it set, sends one PATCH, and records `alfyai-bank-config-2` only after a readback shows config 2. The bank keeps its old version until then, so a lost PATCH is simply sent again by the next attempt; it never holds deliveries, edits, Clear Memory or erasure. The PATCH makes no model call. A bank with no delivery keeps config 1 until its next one, which changes nothing it already holds.

The release is one-way for banks it upgraded: the previous release compares config 1's keys one by one, so it fails every config 2 bank with `native_config_mismatch` (deliveries and edits stop until a roll forward). To roll back:

1. Stop the app's Memory workers (`HINDSIGHT_WORKER_ENABLED=false`, or stop the app).
2. From this release's checkout, with the app's environment loaded, inspect: `npx tsx scripts/memory-bank-config-restore.ts` prints how many live banks hold each config version (counts only).
3. Restore: `npx tsx scripts/memory-bank-config-restore.ts --execute restore-bank-config-1` puts every live config 2 bank back on config 1 with its labels cleared, verified by readback, and its stored version back to `9fb28dbd…`. A bank that fails stays on config 2 and is counted by error code; run it again. It also returns every native account but the tester's to today's Memory page (`unverified`, the count of accounts): an account goes back when one of its banks is restored, and every account once a run leaves no bank on config 2, because the previous release writes facts without labels into any account's banks.
4. Start the previous release. The label rows in `memory_fact_labels` stay for a roll forward; the previous release never reads them.
5. After the roll forward, run the label migration again (runbook, "Label migration"): it labels what the previous release wrote and verifies each account again. It is resumable, and facts it labelled before are skipped.

## Backup, restore and upgrades

Back up the PostgreSQL database (all tenant schemas), AlfyAI SQLite database and secret bundle together, while Memory delivery is paused and no native operation is outstanding. Preserve the exact tested image digest. A database-only backup loses the app's source revisions, erasure fences and credential bindings. A SQLite-only restore can point at mismatched native state. Restore into isolated private endpoints and keep the restored app unable to reach the original native service. Stop the original before reusing its endpoint. Preserve its worker ID and opaque IDs/key versions, then test capability identity, two-tenant isolation, publication and pending delivery/erasure recovery before enabling workers. Keep Memory inaccessible until post-backup erasures, resets and revocations have been reapplied from verified current records. Leave it inaccessible if that history is unavailable.

### Restore hold

1. Restore the candidate pair in isolation. Keep the restored native API and workers stopped, and keep the app out of public routing.
2. Always set `HINDSIGHT_RESTORE_HOLD=true` on the isolated app before starting it with a restored SQLite file. Every app HTTP route returns 503, including health and machine routes, and workers do not start. Any explicit value other than `false` holds the instance. The hold comes from the deployment environment and requires a restart to change.
3. Verify the current privacy decisions offline. An older pair can contain acknowledged erasures' former rows and queued write intents. Reconcile the candidate against authoritative newer erasure, reset and removal records before serving or running native work. A separately verified newer matched pair that already includes those decisions can replace the held candidate. If the current records are unavailable or reconciliation cannot be verified, keep the old pair held.
4. After offline verification, start the verified native service privately. Clear the hold on that verified SQLite pair only, then verify memory readback and pending cleanup before admitting traffic. Changing the setting alone does not reconcile the backup.

An engine upgrade is a new acceptance run: observed pin/config, tenant isolation, native source replay, edit/remove/dependency lifecycle, outage recovery, current-list publication, local-model capacity and backup/restore. Do not use a floating upstream tag. The current local synthetic evidence is linked from `docs/plans/hindsight-memory/implementation-native-operations.md`; deployment-equivalent container/restore acceptance must be distinguished from local pg0 tests.
